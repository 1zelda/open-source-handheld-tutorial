Win11 家庭版局域网文件共享完整操作手册
一、核心成功公式（必须按顺序执行）
plain
非系统盘独立文件夹 + 本地账户（必须有密码）+ 共享权限/安全权限双完全控制 + 访问端 net use 预连接 + dir 验证 + 资源管理器打开
二、正确操作步骤（掌机/服务端）
1. 确认网络
Win + R → cmd → ipconfig，记下 IPv4 地址（如 192.168.2.13）
确保掌机和访问端连同一个 WiFi/路由器
2. 创建本地账户（如果只有微软账户）
设置 → 账户 → 其他用户 → 添加账户
"我没有这个人的登录信息" → "添加一个没有 Microsoft 账户的用户"
用户名如 one 或 ROG，密码必须设（如 123456）
3. 启用账户并确认密码
cmd
net user 用户名 /active:yes
net user 用户名 密码
4. 创建共享文件夹（关键避坑）
在 D/E 盘根目录新建文件夹（如 D:\Share 或 C:\Share）
❌ 禁止共享：桌面、Users、Windows、Program Files、整个 C 盘根目录
❌ 禁止共享 D 盘根目录后试图访问子文件夹（父目录权限会拦截）
5. 设置双权限（最容易遗漏）
右键 Share 文件夹 → 属性：
表格
选项卡	操作路径	必须勾选
共享	高级共享 → 权限 → 添加本地账户	完全控制
安全	编辑 → 添加 → 输入本地账户名 → 检查名称	完全控制
两个都要加，缺一不可。 共享权限管"能不能看到"，安全权限管"能不能读写"。
6. 打开系统级共享开关
控制面板 → 网络和共享中心 → 更改高级共享设置
专用网络：启用网络发现、启用文件和打印机共享
所有网络：关闭密码保护共享（可选，如果已用账户密码连接可不管）
三、正确操作步骤（访问端/电脑）
1. 清除旧凭据缓存（必须）
cmd
net use * /delete /y
2. 建立带密码的连接（必须）
cmd
net use \\192.168.2.13\Share /user:用户名 密码
示例：net use \\192.168.2.13\Share /user:ROG 850731
3. 命令行验证底层是否通了
cmd
dir \\192.168.2.13\Share
能列出文件 → 底层通了
报错 → 查下表定位问题
4. 资源管理器打开（三种方式）
Win + R：\\192.168.2.13\Share 回车
资源管理器地址栏：直接输入 \\192.168.2.13\Share
cmd 跳转：explorer \\192.168.2.13\Share
5. 传文件（双向复制粘贴）
从掌机到电脑：在 \\IP\Share 窗口里选中文件 → Ctrl + C → 粘贴到电脑本地文件夹
❌ 错误：在掌机里复制，到电脑右键粘贴（剪贴板不跨设备）
四、失败问题与解决方案对照表
表格
问题	现象	根因	解决方案
ping 不通	"请求超时"	不在同一 WiFi；防火墙拦截 ICMP	确认同一路由器；掌机关闭防火墙测试
IP 变了	昨天能连今天不行	DHCP 重新分配	掌机重新 ipconfig 查新 IP
微软账户被禁用	"此用户无法登录，因为该账户当前已被禁用"	SMB 只认本地账户	创建本地账户，禁用微软账户做服务端
空密码被拒绝	net use 成功但 dir 报"拒绝访问"	Windows 硬性禁止空密码网络登录	必须设密码；或改注册表（不推荐）
密码错误	"系统错误 1326"	密码不一致或以为没密码	掌机 net user 用户名 新密码 强制重置
只设共享权限	能看到文件夹，打不开文件	没开安全权限（NTFS）这道门	安全选项卡也加账户 → 完全控制
只设安全权限	\\IP 看不到文件夹	没开共享权限这道门	共享选项卡也加账户 → 完全控制
共享系统目录	权限界面显示加了，实际进不去	UAC/系统策略覆盖手动权限	换到非系统目录新建文件夹（如 D:\Share）
共享 D 盘根目录	\\IP\d 能进，\\IP\d\子文件夹 拒绝	父目录（根目录）权限拦截子文件夹	不要共享根目录，单独共享一个子文件夹
凭据缓存混乱	权限改对了还是连不上	访问端记住了旧身份	net use * /delete /y 清缓存后重连
cmd 里直接输 \\IP	"文件名、目录名或卷标语法不正确"	\\IP 是资源管理器语法，不是命令	cmd 里用 net use、dir 或 explorer
资源管理器无反应	net use 成功但窗口空白	资源管理器进程缓存旧状态	任务管理器重启"Windows 资源管理器"
关机后连不上	重启后访问报错	net use 会话断开，需重建	重新执行 net use \\IP\Share /user:用户名 密码
多台设备账户不通用	新机器上检查名称找不到账户	本地账户只在创建它的那台机器上存在	每台机器各自创建本地账户，或用该机器已有的本地账户
"关闭密码保护共享"失效	保存后自动变回"启用"	微软账户绑定 PIN，系统强制覆盖	放弃此方案，改用本地账户+密码
错误 1219	"不允许一个用户使用一个以上用户名"	同一 IP 缓存了不同身份	net use * /delete /y 彻底断开再重连
错误 67	"找不到网络名"	共享名拼错；或该文件夹未设置共享	确认共享名；不要在路径里用子文件夹名代替共享名
五、无用功（做了等于白做）
反复在桌面/Users/C盘系统目录里调权限：系统策略会覆盖，死磕没用
反复改权限但不清 net use 缓存：访问端用旧凭据，掌机改得再对也白改
共享整个 D 盘根目录：子文件夹继承混乱，不如单独共享一个文件夹
反复开关"网络发现"：全局开关开一次就行，99% 的问题不在这
用 Everyone 测试后忘了删：等于局域网裸奔，安全隐患
六、禁忌（千万不能做）
表格
禁忌	后果
❌ 用普通 USB-A to A 线直连两台电脑	两台都当 Host，可能烧接口
❌ 共享 C 盘根目录/Windows/Program Files	权限复杂，误操作可能破坏系统
❌ 用微软账户做 SMB 共享服务端	Win11 家庭版不认微软账户，直接禁用
❌ 指望空密码能通 SMB	硬性禁止，必须设密码
❌ 把 Everyone 永久留在权限里	局域网内所有设备都能访问，裸奔
❌ 不清缓存就反复试不同路径	\\IP\d 和 \\IP\Users 凭据分开缓存，必须统一清理
七、快速重连（关机/重启后）
掌机 ipconfig 确认 IP
访问端：
cmd
net use * /delete /y
net use \\192.168.2.13\Share /user:用户名 密码
dir \\192.168.2.13\Share
Win + R → \\192.168.2.13\Share
八、一劳永逸方案（映射网络驱动器）
访问端"此电脑" → "..." → 映射网络驱动器
文件夹：\\192.168.2.13\Share
勾选 "登录时重新连接"
勾选 "使用其他凭据连接" → 输入用户名密码 → 记住凭据
以后开机直接双击 Z 盘，无需再输命令。

核心教训：Windows SMB 共享有三道门（网络、共享权限、安全权限）和一个隐藏关卡（凭据缓存）。任何一道门没开，或者用了错误的钥匙（微软账户、空密码），都会卡在奇怪的地方。最干净的方案就是：非系统盘独立文件夹 + 本地账户有密码 + 双权限完全控制 + 访问端先 net use 再打开。
