0. 一页结论

  1. 新闻/文章入口已经自动跨域，不再要求先手选 LOL、DOTA2 或复古游戏库。

问句命中几个已登记域，就分别查几个域；显式 game/revision/platform 仍是最高权限的人工身份覆盖。 多域结果绝不合并成一个总 pass。【已落地】

  1. 查询留痕已经能追到“这次到底用了哪份索引”。

每个唯一问题一行，关联全部 event_id，记录最终裁决、自动域、证据定位和实际索引的完整 index_sha256；不落正文全文或凭证。【已落地】

  1. 《热血格斗传说》已经建成“版本锁定角色创建”的证据底座。

官方页与日版说明书证明四输入、六项能力、四种格斗类型、10 种个人必杀、两种合体技形态； 原版 FC 与 DvD Rev.B 补丁已隔离。【已落地】

  1. 最难、也最容易造假的公式没有冒名攻克。

二手 FAQ 给出 KT# = (出生月 + 出生日 - 1) mod 20 和星座相性表，但原站未取回、未由本机 ROM 复算， 所以仍是 reference_only。名字/血型到能力或格斗类型的公式仍未解。【未证明】

  1. 当前生产明确走 BM25，不偷偷启用语义层。

kb_dense.ready(hybrid) 实测返回“稠密指纹件未建”；A2 未获批准，本轮没有重建向量件。【实测+待批】

1. 自动跨域调用到底怎么工作

1.1 生产链路

真实入口是：

新闻事件 / 文章问题
  → 选题决策层/知识对照.py: crosscheck()
  → taspipe/kb.py: query_auto()
  → taspipe/kb_route.py: route_many()
  → 每个命中域分别调用 kb.query()
  → 新闻层做域锚定降级
  → 查询日志记录最终裁决

关键实现位置：

  • kb_route.py:18：新增 retro_fighting 域。
  • kb_route.py:182：route_many() 自动返回全部命中域。
  • kb.py:870：query_auto() 单域/多域分派与聚合。
  • 知识对照.py:123：新闻生产入口调用 query_auto()，调用方不传 domain。

1.2 路由规则

  • 强词命中时，只走强词命中的域，避免“赛程”等共享弱词把所有电竞域拖进来。
  • 没有强词时，并列保留全部弱词命中域，不擅自二选一。
  • ASCII 词按字母数字边界匹配，避免 tas⊂Fantasy、eck⊂check、LOL⊂Lolita。
  • 拳皇、冠军 列入 AUTO_WEAK_STOP：它们只能说明品类/赛事，不能证明具体游戏或版本。
  • 未识别实体不等于不存在；coverage_note 明确说明路由只覆盖已登记词，不能借其他域证据代答。

因此，“全自动”准确含义是：在已登记知识域内自动选择并查询，不要求人工先选库。 它不等于无需维护别名表，也不等于能猜出文中完全没出现的实体。新游戏仍必须先登记域、版本和语料。

1.3 多域为什么不能合并成 pass

假设同一问题同时命中 LOL 与 DOTA2：

  • 两域都无料：总 miss/out_of_scope；
  • 任一域异常：总 inconclusive/multi_domain_error；
  • 任一域有硬证据：总 inconclusive/multi_domain_needs_split；
  • 其余：总 inconclusive/multi_domain_incomplete。

总结果的 selected_evidence=[]，逐域证据留在 domain_results。下游必须把事实拆开，逐域出证， 不能把“LOL 有答案”拼成“整个联动问题已答”。

1.4 新闻层还有一道域锚定门

即使全库词面检索给出 pass，只要自动路由没有锚定游戏内容域，新闻层也会降为 inconclusive/unanchored 并清空 selected_evidence。运行记录用 unanchored_downgraded 记受影响卡数，不静默放行。

本轮真实反例：

SCS 2026年度总决赛落幕 《拳皇15》 选手夺冠

最终是 inconclusive/unanchored、0 条证据，不再被“冠军”误拖成 LOL，也不能拿内部文档冒充新闻硬证据。

2.3 为什么仍走 BM25

本轮调用生产函数 kb_dense.ready(hybrid_index) 得到：

(False, "稠密指纹件未建（py -3 -m taspipe.kb dense）")

hybrid 索引文件存在，不等于 hybrid 检索可用。稠密增强要求当前索引对应的 .npz 指纹件存在、 sha 一致、块数对齐且模型依赖可导入；任一条件不满足就明确退回 BM25，并在结果里写明 bm25_only。

A2 语义层尚未获批准，因此本轮没有执行 kb dense，也没有调用外部模型或付费 API。

  • HP
  • 手投
  • 足投
  • 投げ技

  • バランスタイプ
  • マーシャルアーツタイプ
  • カンフータイプ
  • くのいちタイプ

这些是后续做角色计算器、随机角色生成器、版本对照和自动问答都可以复用的 schema。

4. 最难的一块：公式到底攻克到哪一步

4.1 已解决

  • 把“角色创建”拆成了输入、能力、格斗类型、个人必杀、合体技、相性、版本边界七个可验证面。
  • 每面都能指向具体来源和 revision，不再靠一段泛泛攻略回答所有问题。
  • 公式类问句有了独立答案形态闸门：必须出现真实公式/算式，不能拿“官方说输入项重要”冒充公式答案。
  • Rev.B 问句必须命中补丁版本形态；原版 FC 不会借补丁的四人能力假 pass。
  • 排他/原生归属问句必须命中完整归属形态，避免“非原生者”被当成“谁是原生角色”的答案。

4.2 仍是二手候选

FAQ 给出：

KT# = (出生月 + 出生日 - 1) mod 20

并有 20 行 KT 表与 12 星座日期/相性表。它可用于：

  • 本地候选计算；
  • 设计后续 ROM 复算实验；
  • 给玩家做明确标注的参考工具。

它不能用于：

  • 权威级“某生日必然获得某必杀”的硬结论；
  • 自动文稿里不带出处地陈述；
  • 与官方说明书能力混成同一等级。

原因：FAQ 的表注明 adapted from rahga.com/nkd/，本轮直接访问原站失败；KT 表和相性表也未由本机原版 ROM 逐例复算。

4.3 仍未解决

  • 名字到六项能力的公式；
  • 名字到格斗类型的公式；
  • 血型到具体能力值的公式；
  • rahga.com/nkd/ 原始页面或可信快照；
  • KT/星座表的本机 ROM 复算。

所以当前状态是：可复用框架和官方骨架已攻克，最硬的数值公式仍保持未证明。 这比把二手表升成权威更可靠，也不会让后续所有游戏继续踩同一个坑。

7. 用户第 2 项“NICE 试一下”怎么理解

当前生产链里没有一个名为 NICE 的开关。若你指的是“带语义理解的 hybrid 检索”，实际效果是：

  • 先用 BM25 召回；
  • 再用本地嵌入模型与重排模型改变候选顺序；
  • 需要与当前索引完全匹配的稠密指纹件和模型依赖；
  • 缺任一项就明确退回 BM25。

本轮没有把“试一下”当成启用语义层、下载模型、调用付费 API 或发送授权邮件的批准。 当前 hybrid 未就绪原因已实测为“稠密指纹件未建”，生产 smoke 均明确记录 bm25_only。

9. 下一步建议（按价值排序）

P0：用真实问题检验自动路由

  • 继续从新闻生产入口积累唯一问题日志；
  • 每周人工标注少量“应命中哪些域、最终该不该 pass”；
  • 重点看只有品类词、跨游戏联动、版本别名、中英混写四类；
  • 发现漏路由先补别名/焦点词，不直接上语义模型。

P1：把《热血格斗传说》KT 表做成“可复算候选实验”

  • 输入：出生月、出生日；
  • 计算：(月 + 日 - 1) mod 20；
  • 输出：候选 KT 集合，并醒目标注 reference_only/未经 ROM 复算；
  • 后续若取得合法原版 ROM 与模拟器条件，再做受控逐例复算；
  • 未复算前不升级 authority，不进入硬证据通道。

P1：补原站或替代一手证据

  • 再查 rahga.com/nkd/ 的快照、作者归档或同一表的更早出处；
  • 若找到，先登记来源资格，再决定是否替换 FAQ；
  • 找不到就继续保留 provenance gap，不把“查不到”写成“公式不存在”。

P2：片段级来源资格

  • 解决“整份文件权威，导致其中二手转述也权威”的既有问题；
  • 撤回段、转述段、参考表分别有片段级 authority；
  • 这是语义层是否值得重新评估的前置条件。

P2：扩到下一款游戏

复用本次已经验证的七件套：

  1. 版本分区；
  2. 来源分档；
  3. 输入/输出 schema；
  4. 答案形态闸门；
  5. 反例夹具；
  6. 索引指纹；
  7. 查询日志。

接新游戏时仍以“官方骨架 + 明确未证明项”起步，不追求一次性把整款游戏讲完。
