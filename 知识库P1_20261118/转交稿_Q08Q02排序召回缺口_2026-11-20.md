## 1. 系统架构（你的设计空间）

### 1.1 两条检索臂（自动选择）

| 臂 | 索引 | BM25 统计量 | 触发条件 |
|---|---|---|---|
| **bm25 兜底臂** | `index.json`（625 块） | 全局 IDF（N/avgdl 取全索引） | 稠密增强不可用时退回 |
| **hybrid 富集臂** | `index_hybrid.json`（639 块 = 625 + 14 中文对照块） | **域内 IDF**（N/avgdl/df 取候选池内） | 稠密指纹件就绪 + 依赖可导入 |

- 选臂逻辑：`kb.py::_select_index()`（L521）→ `kb_dense.ready()`（L93，不加载模型只查指纹/依赖）就绪则富集+域内，否则 base+全局。
- **域内 IDF 已是 hybrid-conditional**：只在富集臂用域内统计量，兜底臂保持全局。这是已落地的设计，**不要破坏它**。
- 两臂行为差异的根源：兜底臂的出证排序**直接由 BM25 决定**；富集臂的 BM25 只喂候选池，**最终出证由重排器语义排序决定**。所以任何改 BM25 统计量的方案，在兜底臂会直接暴露排序扰动，在富集臂会被重排器吸收。**兜底臂必须零回归。**

### 1.2 hybrid 检索链（`kb_dense.py::enhance()` L129）

```
BM25 候选打分（kb.py::_bm25_scores L538）
  → 稠密向量 BGE-M3（BAAI/bge-m3，MIT，归一化）算 query↔块 余弦
  → 候选池 pool = RRF(bm25_top50, dense_top50) ∪ dense_top12 ∪ bm25_top6
     （RRF_K=60, POOL=50, DENSE_CUT=12, BM25_CUT=6, TOPK=8）
  → 重排器 bge-reranker-v2-m3（BAAI/bge-reranker-v2-m3，Apache-2.0，CrossEncoder，max_length=1024）
     对 pool 内每块 predict(query, text) → 按重排分降序 ranked
  → anchor_top8（L78）：取 ranked[:8]；若 bm25_top1 不在榜内，追加到第 8 席（只保席位不抬名次）
  → 返回 top8 块下标
```

重排器是 **CrossEncoder（判别式），不是生成式 LLM**，允许使用/调整。嵌入与重排都跑 CUDA（5060 Ti 16G），离线本地模型（`HF_HUB_OFFLINE=1`）。

### 1.3 可答性闸门（`kb_answer.py::annotate()` L79，零 LLM，五关）

词命中 ≠ 回答了问题。每个 hit 块过五关：
- **focus**：问句焦点词与块文本重叠（topic/yesno/无聚焦形态的 identity 硬性要求）。
- **pattern**：问句聚焦形态正则命中块文本（如 identity 问"只有哪个角色"→ 块须含"仅 X 原生"这类形态）。
- **intent**：意图校验器（`_intent_ok` L63；yesno 须含 `YESNO_RE` L41 的是非词/隐性肯定形态）。
- **url_list**：≥2 个网址的块判为来源清单，不是答案正文 → 否。
- **topic_anchor**：中文 howto/existence 块须另有焦点词重叠；**日文块不施话题锚**（中文焦点词天然不重叠）。

`answerable = pattern_ok AND intent_ok AND (focus_ok OR not focus_required) AND not url_list AND (anchor_ok OR not anchor_required)`

### 1.4 权威分级与出证判定（`kb.py::query()` L576）

- 权威三级：`authoritative`（官方件/我方实测）> `cross_version`（跨版本参考）> `reference_only`（二手攻略，须交叉核对）。
- **strong** = `verified_read` + 本版本匹配（`*_multi` 实测件对同 game 任一版本算本版本）+ `authoritative`（或问的就是它自己版本的 cross_version）+ `answerable` + 内容词（≥2 字）命中。
- **状态判定（L705–720）**：
  ```
  answerable = [h for h in hits if h.answerability.answerable]
  若 answerable 为空 → INCONCLUSIVE(unanswerable)
  strong = answerable 中满足 _strong + 内容词的
  若 strong 为空 → INCONCLUSIVE
  for rank, h in enumerate(hits[:top_window], 1):   # top_window 默认 3
      if h.chunk_id in strong_ids:
          → PASS（rank>1 时附 condition「权威可答件在第N位，非最高分」）
  否则 → INCONCLUSIVE（「top3 内无本版本权威可答件」）
  ```
- **`top_window=3` 是用户批准口径，不许改默认。**

### 1.5 跨语扩展（`kb_route.py::expand_terms()` L178）

规则式：中文触发词 → 日文表层形式（如"位置"→ポジション、"合作"→協力）。**只影响 BM25 查询侧**，稠密仍用原问句。这是已有的跨语召回手段。

## 5. 护栏（不许碰的）

- **bm25 兜底臂零回归**是铁律：任何改 BM25 统计量/候选池/排序的方案，必须保证兜底臂逐格不变。域内 IDF 已 hybrid-conditional，别把它变成无条件。
- **不改默认窗口、不改冻结金标**（除非单独标注需用户批准）。
- **不引入 trap 假阳**：可答性闸门（§1.3）和权威分级（§1.4）是防"沾话题就冒充答案"的防线，放松它们会让 refuse 格（Q09/Q12-15/Q17/P20-21/P25-26 等）假 pass。
- **新闸门要配反证**：只立闸门不写恒量反证格 = 没验。
- **结果走生产代码路径**：不许临时脚本代跑生产逻辑；验证须用真实 `kb.query` / `prod_eval.py` / `p23_probe.py` 入口。
