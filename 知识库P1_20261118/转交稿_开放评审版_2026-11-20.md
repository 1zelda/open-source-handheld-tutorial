## 这是个什么项目

一个**零生成式 LLM** 的复古游戏知识库检索管线。用户用中文问游戏机制（比如 FC《热血足球联盟》的必杀技、KOF98 某张卡的规则），管线从本地收集的日文说明书扫描件、中文攻略、我方实测记录里检索证据，带**权威分级**和**可答性闸门**出证——宁可拒答也不拿"沾话题的块"冒充答案。

检索栈（`F:\开源掌机教程\_工具脚本\taspipe\`）：
- **BM25 主干**（`kb.py`）：候选打分 + 路由 + 出证判定。
- **可选稠密增强**（`kb_dense.py`）：BGE-M3 向量 → RRF 融合池 → bge-reranker-v2-m3 重排 → 词法锚保 BM25 top1 席位。嵌入/重排跑 CUDA，离线本地模型。
- **可答性五关**（`kb_answer.py::annotate`）：focus / pattern / intent / url_list / topic_anchor，零 LLM，区分"提到话题"和"回答了问题"。
- **两条臂**：稠密就绪走 hybrid（富集索引 639 块 + 域内 IDF）；否则退回 bm25 兜底（base 索引 625 块 + 全局 IDF）。

出证逻辑：top8 命中里，默认前 3 窗口内有"本版本权威 + 可答 + 内容词"的块就 pass，否则 inconclusive。

## 我们遇到的问题（诚实现状）

hybrid 臂现在 26 题冻结评测过 24，剩两题一直是排序/召回层的硬骨头：

- **Q02「燕返原生只有哪个角色会使？」**：精确答案就在库里（必杀全清单的表格行"仅 Yoritsune 原生"），可答性也判它 True，但重排器把它排在第 4，前 3 全是"沾燕返话题却不回答这个问题"的块 → 默认窗口 3 把它挡在外面，判 inconclusive。**重排器不知道可答性，出证又只看前 3。**

- **Q08「双人合作模式下二号玩家操作什么位置？」**：系统其实**答对了**（2P 操作 GK），用的是权威中文对照件。但冻结金标锚的是**日文原件扫描块**，那个块没被召回进 top8——中文问句下重排器偏好内容相同的中文对照块，把日文原件压下去了。同一个金标块，问"每队几名球员"(Q06)能召回到，问这句就召回不到。**跨语召回缺口。**

一路试过的事（给你省点重复劳动）：
- **再索引**（把中文对照块加进索引）：bm25 臂会因全局 IDF 位移回归 + 引假阳，否了；hybrid 臂靠重排器吸收扰动可行。
- **域内 IDF**（N/avgdl/df 取候选池内，隔离跨域位移）：已落地，但只在 hybrid 臂用，bm25 兜底保持全局——因为兜底臂出证直接由 BM25 排序决定，扰动会直接暴露。
- bm25 兜底臂还有个**词法缺口**（W03「守门员能不能用必杀」）：真答案"守门员专用必杀技龙卷风拳"靠词法排不过一个讲规则、含跨语扩展词的高分块。hybrid 重排器能救，bm25 单臂救不动。

更深层的张力我们自己也没完全想清楚：可答性闸门和重排器排序怎么协同？跨语召回该在哪层补（查询扩展 / 嵌入对齐 / 池组成 / 重排）？冻结金标锚定日文原件是否本身就太严？这些都想听你的看法。
