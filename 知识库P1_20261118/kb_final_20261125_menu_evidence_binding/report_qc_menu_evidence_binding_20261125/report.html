  • 并行会话已将该来源明确登记为 candidate。本轮保留该资格，不把单次菜单观察升级为 verified_read，也不把菜单描述外推为玩法或画面检测验收。
  • 来源审计由 element_coverage=fail 修正为 pass：当前 102 条来源、24 个知识包、202 个要素，202/202 有来源支撑；总状态仍为 inconclusive，因为候选与弱资格缺口仍在。

2. 根因与修正

2.1 菜单包未进入来源覆盖

原菜单包没有 catalog.sources，114 个要素也只有 group + id，没有 element_id。原审计对缺 element_id 的要素直接跳过，因此这类包会被静默漏审。

本轮将每个要素绑定为稳定字符串 ID，并在 catalog.sources.element_ids 中逐项列明。来源、状态和 evidence_report 仍由注册表与生产审计函数校验，不在菜单包内另造资格口径。

2.2 证据路径不是有效取证

原包声明的 evidence/menu_catalog_report.json 在项目内不存在；名称与效果观察只位于 scratch 根目录；legacy_patch_audit.path 的文件名也与项目实件不一致。

本轮将所有引用改为项目内真实路径，并逐件复核字节与 SHA-256。原始采集报告保留为 source_capture_report.json，另生成项目内 menu_catalog_report.json，记录 114 项、342 文件、唯一哈希数、总字节数和资格边界。

2.3 审计不再静默跳过

sources.py:689 现在按包统计全部要素；缺 element_id 会进入覆盖失败明细，序号不再代替稳定标识；包内重复 ID 也会失败。

sources_selftest_gates.py:363 增加三条确定性检查：

检查输入预期
[52] 缺稳定 ID要素只有 group/idelement_coverage=fail，明细点名缺 element_id
[53] 重复 ID同包两个要素使用同一 IDelement_coverage=fail，明细点名重复
[54] 候选来源正例稳定 ID + candidate 来源覆盖通过，但 verified_support=inconclusive
