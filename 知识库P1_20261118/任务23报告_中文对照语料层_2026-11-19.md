## 2. 切块器语言陷阱（踩坑，改生产前只读诊断）

`kb.build()` L431-435 是**文件级**判语言：`kana_ratio(整份) > KANA_THRESHOLD(0.30)` → 整份走 `chunk_ja`；`chunk_ja` L347 **硬编码 `lang="ja"`**，无按段判语言。

- 陷阱：把中文追加到日文主导件文末，整份仍被判 ja → 中文段被误标 `lang=ja`，吃 P3 日文豁免、绕过中文话题锚关。
- 实测：setsumei 原件 kana_ratio=0.7092；追加 2040 字中文后降到 0.5276，**仍 >0.30** → 陷阱坐实。
- 规避：用**独立对照件**（中文主导）。实测 setsumei 对照 kana_ratio=0.1515、urawaza 对照 0.2398，均 <0.30 → 走 `chunk_prose` 正确标 `lang=zh`。独立成件比追加文末更严格满足「原件字节不动」。

## 5. Q08 指标仍 FAIL 根因（结构性，语料层治不动）

冻结金标（`p1_questions.json`）：`path_contains="setsumei"`、`line_start=line_end=47`（日文原件 2P 位置行）、expect=gold_in_topk。`eval_common._gold_hit` 要求 path 命中 **且行号重叠**。

- 对照文件虽也含「setsumei」，但答案在 **L7-10**，与金标 L47 不重叠 → `_gold_hit` 不认账。
- 对照真答案块排 **rank8**（排序层缺口，P4 已判）：route game_ids=None（无游戏关键词未路由→全库含 project_docs）+ intent=identity 误判 + 跨语扩展偏日文（ポジション/モード/協力）favor 阵容块词频 + 说明书自身讨论 Q08 的块自污染 top1。
- 结论：Q08 是**排序层/模型能力缺口**，补中文对照只让真答案「存在且可答」，不改排名、不改金标行号 → 指标仍 FAIL。与 P4「Q08 不硬调」先例一致。

## 9. dense 指纹陷阱（踩坑）

`kb_dense.npz_path` L36-38 的指纹是 **index.json 整份字节的 sha256**，不只是块内容。撤回重建虽块内容逐块一致，但 `files` 字典多 2 条排除登记 + built_at 等字节变了 → 指纹从 `a56a3a261f84` 变 `09096a016496` → 旧 npz 失配，hybrid 会**静默退 bm25_only**。

- `enhance()` L104 还校验 npz **内部** `index_sha` == 当前索引 sha → **手抄旧 npz 改名顶包会在 L104 失败**，生产 `kb dense` 重建是唯一正确路径（嵌入内容相同，仅指纹件名/内部 sha 更新）。
- 重建后删孤儿 `embeddings_a56a3a261f84.npz`（已确认未被 git 跟踪、可再生、新件对评测+探针都工作）。仅剩 `embeddings_09096a016496.npz`。
