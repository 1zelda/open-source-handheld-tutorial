## 1. 干了什么（白话）

小样证明"换检索引擎救不了假阳性"。P1 不动引擎主干，在检索前后加了四道规则层：

1. **域路由**（p1_router.py）：问题先判属于哪个游戏/文档域。LOL/DOTA/原神这类
   库内零语料的域直接结构性拒答（not_found_within_scope），不再让热血足球的
   "世界杯"段落去冒充电竞答案。显式强词（游戏名/角色名）优先于弱词。
2. **逐事实可答性核查**（p1_answerability.py）：词命中≠回答问题。每个命中块按
   问句意图校验答案形态——问数量要有"数字+量词"（含日文試合/全角归一、问场不许
   拿"6人制"串答）、问SHA1要有40位hex、问"原生只有谁"答案必须含"原生"归属、
   问转会要有转会/市场事实。全部命中不可答 ⇒ insufficient_evidence，绝不 pass。
3. **语言同质小段切块 v3**（p1_chunker.py）：日文主导文件（kana占比>0.30）按
   `* * *` 章节切 ≤300 字小段并前置章节标题；中文块原样保留 v2（逐块 sha 断言）。
4. **权威策略双轨**：默认 strict_top1 与生产 kb.py 同规则不动；备选 top3_conditional
   （top3 内有权威可答件即附条件出证）只测数字，改不改由用户定。

## 4. 生产接线（已完成，2026-11-19 本轮实测）

决策落定：用户批准推荐口径 **top3_conditional + union12**（"按照你的想法来"）。

清单五条逐项落地（生产代码在 `_工具脚本/taspipe/`）：

1. **kb.build v3 切块**：prose 且清洗后 kana 占比 >0.30 → chunk_ja（原行号、`* * *` 切章、
   ＜…＞标题前置、≤300 字段落打包），块带 lang 字段；ja 块 cid 追加 text_sha 防同行号碰撞。
   PIPELINE 升 `chunk3|ja300` 触发全量重建。中文路径不变。
2. **kb.query 域路由**：新模块 kb_route.py（8 域强词>弱词>unrouted + 6 意图 + 焦点形态）。
   域外零语料且无显式过滤 → miss + refusal="out_of_scope"；显式 game/revision/platform
   过滤优先于域限制。
3. **逐事实可答性**：新模块 kb_answer.py，hits 逐块 annotate 三关（focus/pattern/intent）；
   全不可答 → inconclusive + refusal="unanswerable"；strong 只在可答块里取，
   内容词重叠改按块文本 tokens（覆盖 dense-only 命中）。
4. **union12 融合池**：新模块 kb_dense.py（可选增强）：RRF top8 ∪ dense top12 ∪ bm25 top6
   进重排取 top8。稠密指纹件 embeddings_{索引sha12}.npz，enhance 先验指纹/块数/依赖，
   任一不满足 → 明示退回 bm25_only + retrieval_note（不静默顶包）。模型 CUDA 优先、
   模块级单例、local_files_only。
5. **top3 附条件出证**：top3 内有本版本权威可答件即 pass；非最高分位必带 condition 字段；
   top3 外仍 inconclusive。**状态词表不变**（pass/inconclusive/miss），新语义走
   refusal/condition/retrieval/retrieval_note 字段，下游消费者不破坏。
   CLI query 打印检索路径/附条件/拒答类型；新增 dense 子命令。
