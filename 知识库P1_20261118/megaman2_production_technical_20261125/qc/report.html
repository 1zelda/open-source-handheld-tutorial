这次真正接通的是“提问 → 自动路由 → 生产索引检索 → 来源与版本复核 → 唯一证据块 → 选题对照 → 自动出卡”。8 个技术问题已能用，扩出来的 32 条正例、14 条反例、8 条真实对照和 8 张卡片全部通过。

1. 一页结论

这次干成了什么

  • 洛克人2的技术问题会由 kb.query_auto() 自动进入 megaman2 域，不再依赖手工指定候选索引。
  • 生产索引中有 7 份逐字取证、8 类可答事实：坐标方向、跳跃 Y 轴初速度、攀爬速度、跳跃横向速度、步行速度、加速帧数、减速停止帧数、对象表 Xspd 地址。
  • 每个 pass 都只带 一条 selected_evidence。来源 ID、revision、verified_read、authoritative、取证路径和行号任何一项不成立，都不给出生产证据。
  • X/Y 速度轴有专门反证：问 X 轴却只命中 Y 轴文本时，系统拒绝出证，不把相近数字当成答案。
  • 真实 知识对照.crosscheck() 与 选题卡.render_card_md() 已跑通；卡片里的“KB出证”只使用通过复核的那一条证据。
  • 最终回归为 项目 1551/1551、知识库 336/336、来源库 74/74；生产 base、hybrid 与来源库审计均为 fail=0。

现在可以怎样用

直接向本地自动查询入口提问，例如：

  • “洛克人2 步行速度是多少？” → 返回证据摘录 01.60。
  • “洛克人2 从静止加速需要多少帧？” → 返回证据摘录 7 frames。
  • “洛克人2 从全速停止需要多少帧？” → 返回证据摘录 8 (decimal) frames。
  • “洛克人2 跳跃时 X speed 是什么？” → 返回 01.50，不会误取 Y 轴的 04.DF。

这里的“返回”是带来源和行号的证据摘录，不是大模型临时编写的答案，也不等于整款游戏攻略已经完整。

这次没有做什么

  • 不是整款游戏知识库：全部武器、敌人、关卡、道具、结局与出招表尚未完整覆盖。
  • PAL/美版/日版 ROM 等价未验证：显式问地区 ROM 时返回 version_not_collected，不拿泛 Rockman 2 技术文档冒充地区身份证明。
  • 内存字典、标题目录、TAS 出版物元数据与官方说明书候选材料没有升格为生产权威。
  • 没有把晓月圆舞曲检测器标定当成玩法、语义身份或平台准入验收；相关来源继续保持 candidate。
  • 没有重启后端、提交或推送代码，也没有调用外部生成模型或付费 API。
  • strict 只作为显式影子臂验收；dense 与 NLI 没有评测，也没有升为默认。生产默认仍是 BM25。

3. 生产链路与拒答边界

一条正常问题怎样得到证据

  1. kb_route 识别“洛克人2 / Mega Man 2 / Rockman 2 / MM2”等显式身份词。
  2. kb.query_auto() 将技术问题交给生产版 kb_megaman2.ask(..., production=True)。
  3. 检索使用生产 index.json 与 corpus_map.json，不是历史候选索引。
  4. 证据必须落在 megaman2_nes_tasvideos_rockman2，来源必须是 tasvideos_rockman_data_mm2_extract，并出现在该来源的七份取证清单中。
  5. 可答性检查同时约束单位与语义：帧问题必须出现帧数；速度/坐标值必须出现 NN.NN；X/Y 轴不能互换。
  6. 只有全部检查通过，结果才带唯一 selected_evidence。随后选题对照只把这条证据当作硬依据，出卡时原样带入 locator。

7. 下一步

  1. 继续真实查询回流：冻结样本零错误不代表开放世界永远零错误；新问题要逐条进入抽查与失败样例。
  2. 地区版本单独建证据：只有取得可核验的 PAL/美版/日版 ROM 身份后，才建立对应 revision 并验证能否互用。
  3. 扩展内容仍按来源逐项登记：武器、敌人、关卡等资料不能因为“网上有”就自动升格，候选、参考、跨版本材料继续隔离。
  4. dense/NLI 暂不升默认：等正确性与授权数据稳定后另开评测，不把本次 BM25 结果当成其他检索方法的结论。
  5. 保持失败可见：inconclusive、缺索引、错轴、未生产 revision 与多域复合问题必须继续显式拒答，不能为了好看改写成 pass。

一句话交接： 洛克人2的这批运动与内存表技术事实已经能自动查出、逐条出证并进入选题卡；它是可复核的生产子域，不是完整攻略，也不是跨地区 ROM 的通用结论。
