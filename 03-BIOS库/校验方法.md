# BIOS 校验方法:为什么"文件放了但还是提示缺失"

这是掌机折腾中最常见的一类坑。原因基本逃不出下面 5 条:

## 1. 文件名对了,内容不对(最常见)
网上流传的 BIOS 有很多是**改名版**或被"优化版"污染过的。模拟器是按 MD5 认文件的,不认名字。

**做法**:先跑 `_工具脚本/bios_check.py`,拿到你手上文件的 MD5,再到模拟器自己的 BIOS 页面看它期望的 MD5:
- DuckStation:设置 → 模拟器 → BIOS,列表里每一行都带期望 MD5。
- RetroArch:启动时缺文件弹窗会直接写出期望 MD5。
- PPSSPP:系统信息页显示当前识别到的固件类型(`ProFX 替代` 说明你其实没装官方固件)。
- melonds / RPCS3 / Flycast:各自 BIOS / Firmware 面板。

对照时**以模拟器面板给出的期望值为唯一标准**,不要从第三方博客抄 MD5(抄错一次会让你怀疑整个文件链)。

## 2. 大小写 / 目录层级不对
- Linux 固件(基于 RetroArch 的掌机系统)区分大小写:`SCPH10000.R3303.bin` ≠ `scph10000.r3303.bin`。
- DuckStation 要求结构是 `PSX/PSX.EXE`、`PSX/scph5501.bin`,而不是把文件平铺在根目录。
- PPSSPP 要求 `flash0/` 是一个**目录**,里面是 `font0.dat`、`lh5-4.stg` 等;只放一个 `flash0.bin` 无效。

## 3. 模拟器没指向正确路径
RetroArch 有两个地方要设:
- 全局:`设置 → 目录 → BIOS/固件目录`(通常 `~/BIOS` 或 `/mnt/roms/BIOS`)。
- 核心选项里有些核心(如 Mednafen)还要单独指定。
把文件放进**它实际读取的那个目录**,而不是你觉得的那个。

## 4. 区域版本不匹配
`scph5500`=美版、`5501`=日版、`5502`=欧版。用日版 BIOS 跑美版 ROM 会出现区域判断错乱(颜色制式、启动 Logo、个别游戏卡死)。
土星、Dreamcast 同理:`saturn_bios.bin` 分美/日/欧,DC 的 `dc_boot.bin` 按 HKT 编号分区。
**建议**:三个都放,让模拟器按 ROM 区域自选。

## 5. 需要的是"固件包"而不是单个文件
- PS3:RPCS3 要的是完整的 `PS3UPDAT.PUP`(官方免费下载,不是散文件)。
- Switch 系:要 `prod.keys` + `title.keys` + `package3` 固件三件套,少一个都不行。
- 3DS:要 `sysdata` 里的系统标题,通常靠 homebrew 的 `firmware installer` 一次性装好。

## 快速自查清单

- [ ] 文件真的在模拟器读取的目录里(不是你的下载目录)
- [ ] 跑 `bios_check.py` 拿到 MD5,和模拟器面板期望值完全一致
- [ ] 目录层级/大小写与模拟器文档一致
- [ ] 区域版本齐全
- [ ] 固件包类(PS3/Switch/3DS)用官方安装入口装,而不是手动摆文件
- [ ] 装完**重启模拟器**(多数只在启动时扫描一次 BIOS)
