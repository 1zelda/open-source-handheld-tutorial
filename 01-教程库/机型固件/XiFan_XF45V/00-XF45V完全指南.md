# XiFan XF45V 完全指南(你的机器)

> 先说最重要的一句:**你的机器不是 R36S。**
> 芯片相同(Rockchip RK3326),但屏不同——R36S 是 640×480,XF45V 是 **1024×768**。
> 所以网上 99% 的 R36S 教程(选 dtb、Panel Picker、主题、黑屏自救)对你**不适用**,照抄会黑屏。
> 本指南只讲 XF45V;R36S 那份留作硬件原理参考:`../R36S/00-R36S完全指南.md`。

## 二、我是怎么确认"XF45 就是 XiFan XF45V"的(证据链,你可复核)

上一版 R36S 指南里我写过"XF45 在所有上游资料里找不到"——**那句话是错的,已删除**。
这次我用四条互相独立的证据锁定了它:

1. **支持表**:arkos4clone 仓库 `Changelog.md:218` 明确列出
   `XiFan[Mymini,Mini40,R36Max,R36Pro,XF35H,RF35H,XF40H,RF40H,DC35V,XF40V,DC40V,XF28,R36MAX2,XF45V,DC45V,RF45V]`。
2. **机型配置**:wiki `Home.md` 的 XiFan 表有 `| XF45V | 768P | consoles/xf45v/ |`;
   `dtbTools/internal/console/config.go:559` 有 `RealName:"xf45v", Brand:"XiFan HandHelds", DisplayName:"XiFan XF45V"`。
3. **真机文件**:仓库里存在 `boot/dArkOS/consoles/xf45v/{boot.ini, rk3326-xf45v-linux.dtb}`。
4. **分辨率反查(关键)**:我没信"768P"这种目录名,直接解析那块 `.dtb`(Windows 上没有 dtc,所以自己写了只读解析器
   `_工具脚本/dtb_peek.py` / `_工具脚本/dtb_panel_sweep.py`),得到
   `/dsi@ff450000/panel@0/display-timings/original`:`hactive=1024, vactive=768, clock-frequency=62000000`。
   同一份 `logo/768P/logo.bmp` 是 2,359,352 字节 = 1024×768×24bit + BMP 头 → 第三重印证。
   上游 `console-detect` 的 `resolution_map` 里 `"768p" → 1024×768` → 第四重印证。

另外顺手澄清一个坑:`dArkOSen-R36S` 仓库里 `grep xf45` 会命中
`opt/system/System/R36.Tuner.Next.sh` 里的 base64 载荷——那是**误匹配**,不是支持。

### 全机型屏幕真值表

我扫了 119 个 `.dtb`(本地 arkos4clone clone 的 91 个机型目录,每个一份 `.dtb` + R36S-DTB 的 28 个面板集;
`consoles/` 里除机型目录外还有 `dtbo/ kernel/ logo/` 三个非机型目录,本地 clone 共 94 个目录。**今天现查上游 `boot/dArkOS/consoles` 是 95 个目录**(比这份 HEAD=9a3e630、2026-09-30 的 clone 多 1 个机型),结果落在
`05-硬件与机型资料/屏幕真值表.md`(可读)和 `panel_specs.tsv`(机器读)。
**两份产物口径不同,别当成矛盾**:`panel_specs.tsv` 是 1 行表头 + **119 行数据**(每个 `.dtb` 文件一行);
md 表格只有 **109 行**,因为同名/同面板的条目合并展示了。两个数本轮都现数过。
跟你的机器同一档 1024×768 的还有一批:`dc45v` `rf45v` `rf45h` `r36max2` `r36ultrax` `h7` `go2` `r46h` `r45h` `r40xx*`。
**这些机型的教程/theme 你可以互相参考;640×480 的 R36S 教程要打个折扣看。**

⚠️ 那张表里的"尺寸mm / 对角寸 / DPI"三列**整列不可信**:dtb 里 `width-mm/height-mm` 是厂商复制粘贴的默认值
(XiFan 全系和 clone 全系都写 153×85,而 1024×768 的 R46H 又抄成 R36S 的 52×70)。寸数请自己卡尺量或看商品页。

## 三、1024×768 带来的真实差别(这才是重点)

RK3326 的 GPU 就那么大。1024×768 = 786,432 像素,R36S 的 640×480 = 307,200 像素,**2.56 倍**。
后果是可量化的:

| 方面 | 影响 | 你可以怎么做 |
|---|---|---|
| EmulationStation 主题 | 为 640×480 做的主题会缩放过糊或留黑边;`768P` 这一档才有合适素材 | 只用上游标 `768P` 的主题/logo;别拿 R36S 主题硬套 |
| RetroArch 视口/整数缩放 | 同一款游戏能拿到更高整数倍缩放,**这是好事** | 见下面的整数倍表 |
| 3D 平台(PS1/N64/DC/PSP) | 渲染像素与 UI 合成开销上升,帧率比 R36S 更吃紧 | 内部分辨率别拉高;N64/PS1 保持 1×,关抖动/滤镜 |
| PortMaster 移植 | 端口按 640×480 写的会居中留边;`device_info.txt` 会把你的机器识别成 `hires`(≥960 宽) | 见第七节的设备名指认 |

**整数缩放对照(我按像素数算的推荐值,不是上游给的结论)**:在 1024×768 上

| 平台 | 原生分辨率 | 推荐整数倍 | 输出 | 备注 |
|---|---|---|---|---|
| GB/GBC | 160×144 | 4× | 640×576 | 还有余量,喜欢大字号可 5×=800×720 |
| GBA | 240×160 | 4× | 960×640 | 接近满屏,几乎无黑边 |
| SFC/FC | 256×224 | 3× | 768×672 | |
| PS1 | 320×240 | 3× | 960×720 | 别开 2×内部渲染 |
| N64 | 320×240 | 2–3× | 640×480 起 | 1GB RAM,先 2× 再试 3× |
| PSP | 480×272 | 1× 渲染 | 上采到屏 | 2× 就 960×544,显存与 GPU 都吃紧 |

RetroArch 里对应:`video_scale_integer = enabled` + 按需 `custom_aspect_ratio_1`。

## 五、刷 ArkOS4Clone(把你机器刷起来的完整步骤)

### 0. 前提
- **插着电源开机**;上游要求原始机电池 > 3.3V(`Home.md`)。
- 只能 **TF 卡启动**,`Installation.md` 写明 eMMC 安装尚未支持。20261008 的 release note 新增的是
  `Added support for writing dArkOS4Clone to eMMC`(**只有 dArkOS4Clone 那支能写进 eMMC,ArkOS4Clone 仍只 TF**)——两处口径的原文都列在
  `02-模拟器库/已clone仓库/系统镜像/README.md` §2.4,我没有替你选。
- 卡片:≥32GB、A2/U3 以上的正规卡(杂牌卡是黑屏与卡顿的第一大来源)。

### 1. 写卡
本机 `ArkOS4Clone-20261008.img.xz`(4,382,690,752 B)已通过 `xz -t` 整流 CRC64 校验,并解出 `ArkOS4Clone-20261008.img`(12,884,901,888 B = 恰好 12 GiB);
上一版 `ArkOS4Clone-20260930.img.xz` 也验过,仍留在盘上备用。SHA256 逐条记录在
`02-模拟器库/已clone仓库/系统镜像/README.md`。
**写卡优先用已经解出来的那个 `.img`**(工具兼容性最稳);直接喂 `.img.xz` 只有 rpi-imager 这类明确支持的工具可以,
Rufus/USB Image Tool 请先解压成 `.img` 再写。工具本地都下好了,哈希在 `09-刷机工具/README.md`;
balenaEtcher 被 dArkOS 上游明写"大量用户报失败,不要用"。
- 不要写 `.7z.001/002/003`(那是外层分卷)。
- 上游提醒过不要用 WinRAR 解压镜像;`7zr` 才是正确工具(本机 `C:\Users\Administrator\.qoder\bin\7zr` 已可用)。

写出来的分区结构(我直接解析了镜像的 MBR,不是我猜的):

| 分区 | 类型 | 容量 | 作用 |
|---|---|---|---|
| p1 | FAT32 | 268 MB | `BOOT`:boot.ini / Image / uInitrd / dtb / logos |
| p2 | ext4 | 11.81 GB | 系统根分区 |
| p3 | exFAT | 789 MB | `ROMS`:首次开机由 `expandtoexfat.sh` 扩到整卡剩余空间 |

### 2. 让系统认出你的机器(最关键一步)
**新刷好的卡,BOOT 根目录里没有 `boot.ini`、也没有任何 `.dtb`。** 本轮用 `_工具脚本/列出BOOT分区.py` 解析
`ArkOS4Clone-20261008.img` 的 FAT 目录项,根目录实测只有 12 个条目:`boot/`、`consoles/`、
4 个平台的 `dtb_selector_*`、`uInitrd`、`clone.sh`、`expandtoexfat.sh`、`fstab.exfat`、`firstboot.sh`、`System Volume Information/`。
机型文件按机型分在 `consoles/<机型>/` 里,所以**"刷完就亮"这件事不存在**,必须先把 xf45v 那一套复制/链接到 BOOT 根
——正常做法就是双击卡里自带的 `dtb_selector_win32.exe`(手动做法见下面第 4 步)。

`BOOT:\boot.ini` 里这一行必须指向 xf45v:
```
load mmc 1:1 ${dtb_loadaddr} rk3326-xf45v-linux.dtb
```
上游 `consoles/xf45v/` 今天的实际内容(本轮 `gh api` 现查):`boot.ini` 992 B + `rk3326-xf45v-linux.dtb` 95,017 B + `5.10/` 子目录。

我对本地 clone(HEAD 9a3e630)里 `consoles/` 下全部 **91 份 `boot.ini`** 做了逐字节 diff。**结论比"只差 dtb 文件名"更细**,别照旧说法抄:
- 91 份的 `load mmc … dtb` 行**各不相同**(91 个不同 dtb 名),这是主要差异;
- 把这一行剔除后,正文仍有 **6 种变体**:74 份是同一版(`fbcon=rotate:0`,带 `quiet`,无 `vt.global_cursor_default`),
  **xf45v 和 r36max2 都在这 74 份里**;另外 17 份分成 5 组,差异全在第 12 行的 `bootargs`:
  `fbcon=rotate:` 1/2/3(dr28s·r40s·r50h·r50s·rg351p·rgb10·rgb10max1/2·rgbv10·rp1·u8 panel1/2 = rotate:3,
  a10miniv4 = rotate:2,rf55h + xf28 = rotate:1)、`vt.global_cursor_default=0` 的有无(rf45h / rf55h / xf28 / a10miniv4 / dr28s 那 12 份都带),以及 r36splus 少了 `quiet`。
- ⇒ **抄别机型的 `boot.ini` 会同时改掉 dtb 和屏幕旋转**,画面方向跟着错;要换机型就用 `dtb_selector`,别手改。

仓库里 xf45v 自带的现成文件在
`02-模拟器库/已clone仓库/R36S专用/arkos4clone/boot/dArkOS/consoles/xf45v/`(把里面的 `boot.ini` 覆盖到 BOOT 根即可)。

> 🚫 **绝对不要重命名 `.dtb` 文件。** 系统的识别逻辑(`console-detect`)是:
> 打开 `/boot/boot.ini` → 找含 `${dtb_loadaddr}` 的那行 → 取后面的文件名 → 查内置表。
> **查不到就默认把你当 R36S**(源码 `console_detect.c:332-379`),那时旋转、热键、LED 全按 R36S 配,画面和按键都会不对。

如果你要手挑文件,`Installation.md` 的手动配置就是四件:
`boot.ini` + 对应 `.dtb` + `consoles/kernel/{original|arkos4clone_fix}/Image` + `consoles/logo/768P/logo.bmp`。
Windows 用户也可以用官方 `dtb_selector.exe`(它是构建镜像时编译的工具,在 release/BOOT 里未必现成——所以我上面给的是**手动路径**,更可靠)。

### 3. 电池驱动选哪个
`consoles/kernel/` 下有两份 `Image`,都是 12,083,208 字节,但 `cmp` 确认**内容不同**(不是同一个文件复制两份):
- `original` — 和 ArkOS R3XS 一致的原厂 rk817 电池驱动。
- `arkos4clone_fix` — 上游重写的驱动:库仑计+电压混合估计、平台区 30 分钟轻校准、满电"峰值驻留 15 分钟"解决卡在 99%、老化 FCC 补偿、唤醒不跳电(`Home.md` §3.1.5)。

**建议先用 `arkos4clone_fix`**;若出现电量乱跳/关机异常,换回 `original` 再试(换法就是替换 BOOT 根的 `Image`)。

### 4. 首次开机
- 第一次启动会展开文件系统,**最长等 10 分钟**,期间别断电、别按面板组合键。
- 屏幕出现 `arkos for clone lcdyk ...` 的文字界面就是在写机型缓存与装依赖。

### 5. 一键中文(上游代码里翻出来的实用开关)
在 BOOT(FAT)分区根目录**新建一个空文件,名字叫 `.cn`**,然后开机。
`clone.sh:483` 见到它就会一次性把:EmulationStation → `zh-CN`、RetroArch → 简体中文、PPSSPP → `zh_CN`、
ScummVM → `zh_Hans`、时区 → `Asia/Shanghai`,做完自己删掉这个文件。(同理有 `.ko` 做韩语。)

## 六、按键、热键与诊断入口

`console_detect` 对你机型的完整判定(`console_detect.c:133`,权威):

| 字段 | 值 | 含义 |
|---|---|---|
| resolution | `768p` → 1024×768 | |
| joystick | `dual` | 双摇杆 |
| hotkey_type | **`happy5`** | 有 FN 键那一类:**FN 当热键** |
| rotation | `0` | 原生横屏,不需要旋转 |
| led_type | **`ws2812`** | 幻彩灯(可编程序;上游有 `JoyLed` 反编译仓库) |
| otg_type | `manual` | 上报字段;开机脚本里我没 grep 到消费点,所以别指望它自动切换 USB 主机模式 |
| volume_type | `adc` | 音量用电位器 ADC 读,不是按键模拟 |

热键表(有 FN 的机器一律 `FN+键`;`Home.md` §6):

| 组合 | 功能 | 组合 | 功能 |
|---|---|---|---|
| FN+X | RetroArch 菜单 | FN+Y | 显示 FPS |
| FN+R1 | 快进 | FN+R2 | 存档 |
| FN+L2 | 读档 | FN+方向键上/下 | 亮度 |
| FN+方向键左/右 | 音量 | FN+Start | 退出游戏 |

PPSSPP:`R3` 或 `L2+R2` 开菜单;Drastic-KK:`Select+Y` 小菜单、`Select+B` 双屏/单屏、`Select+X` 主菜单。

**三个诊断入口**(出问题先看这里,别急着重刷):
1. `/boot/clone_log.txt` —— 每次开机被 `clone.sh` 清空重写,里面第一行就是
   `Device: xxx, 1024x768, joy=2, hotkey=happy5, rot=0, led=ws2812`。**在 Windows 上打开 BOOT 分区就能读到**,
   这是判断"系统有没有认出 XF45V"最快的方法。
2. `/boot/.console` —— 缓存的机型名。**删掉它 = 强制重新检测**(上游也用它来还原被改乱的按键映射)。
3. `sudo console_detect --json` —— 设备上直接跑,看它眼里你的机器是什么。

## 七、Ports / 移植游戏(XF45V 的特殊处理)

### 问题
PortMaster 的权威目录 `PortMaster-Info/devices.json` 里 40 个设备**含 `r36s`,不含 `xf45v`**,
而 `console_detect` 之外还有一条独立的路径:`device_info.txt` 会读 `/proc/device-tree/model`,
你的 dtb 里那个值是 **`XiFan XF45V`**(用 `_工具脚本/dtb_peek.py` 解 `rk3326-xf45v-linux.dtb` 根节点可见),
于是 PortMaster 界面里机型名显示成 `xifan_xf45v`。

### 但这**不会**让可装列表变空 —— 我先前在这里写反了,现已用代码核实并更正

- 装机时的过滤走**能力标签**:`harbourmaster/harbour.py:1154` 取 `device['capabilities']`,
  交给 `util.py:700 match_requirements()` 判定;
- `ports.json` 里那份 `attr.avail` 设备白名单**只被网站使用**(`PortMaster-Website/docs/js/games_fuse.js`),
  设备上没有任何脚本读它;
- 你机器上报的能力是实时探测的:`aarch64 + 1024x768 + 4:3 + hires + analog_0/1/2 + 1gb`
  (`device_info.txt:973-996`,分辨率取自 `/sys/class/drm`)。
  反查 1393 个 r36s 条目:要求 `power`/`ultra` 的是 **0 个**(rk3326 本来就被 `device_info.txt:955-971` 排除在高档之外),
  要求 `!lowres` 的 49 个与要求双摇杆的 37 个你**都满足**。

### 那 `.CUSTOM_DEVICE` 还写不写?——可选,只借机型标签

```bash
echo r36s > /home/ark/.config/.CUSTOM_DEVICE
```

作用范围仅限:缓存文件名 `device_info_<cfw>_<device>.env`、界面显示的机型名、以及按机型名索引的按键预设
(老版 bash PortMaster 更吃这一套)。它**不会**把系统骗成 640×480,因为分辨率永远实测。
不写也能正常装、正常玩;写了只是界面里机型名统一成 r36s 那一类。
少数硬编码 640×480 的端口会居中留黑边,不会错位。

## 八、这台机器的性能天花板(实话)

| GB/GBC/MD/SFC/FC/PCE | 满速 | 放心装 |
| GBA | 满速(mGBA/gpSP;gpSP 支持 EZODE 震动与 mGBA 金手指) | |
