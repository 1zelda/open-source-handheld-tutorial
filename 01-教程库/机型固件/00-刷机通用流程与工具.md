# 刷机通用流程与工具（2026-11-05 复核）

> 这篇管的是**所有开源掌机刷机的公共部分**：怎么下载、怎么校验、怎么写卡、怎么选机型（dtb）、怎么进刷机模式、失败了怎么退回去。
> 机型专属的差异写在同目录的机型指南里：`R36S/00-R36S完全指南.md`、`R36MAX2/00-R36MAX2完全指南.md`、`NGP45HT/00-NGP45HT完全指南.md`、`XiFan_XF45V/00-XF45V完全指南.md`。
> 本文每条结论后面都标了来源；**凡我没实测到的，都明写"未实测"**，不要当成保证。

## 〇、先分清三条刷机路线（走错路线比走慢更糟）

| 路线 | 干什么 | 什么时候用 | 风险 |
|---|---|---|---|
| **A. 写 TF 卡**（最常用） | 把 `.img` 写进 microSD，插卡开机 | 99% 的情况。想试新系统、怕刷坏、机器双卡槽 | 低。卡拔下来原卡插回去就是原来的系统 |
| **B. eMMC 线刷** | 用 USB 线连电脑，进 RK 刷机模式，把系统直接写进板载存储 | 机器**只有 eMMC 没卡槽引导**、或卡槽坏、或原厂系统装在内置存储（如部分 EmuELEC 克隆机） | **高。写坏了机器可能开不了机**，且原厂系统会被覆盖 |
| **C. 系统内 TF→eMMC 克隆** | 先按 A 刷 TF 卡，进系统后跑一个脚本把卡上的系统复制到 eMMC | 已经能正常从卡启动，想去掉卡 | 中。选错盘会毁数据 |

一句话建议：**先 A，A 成功了再考虑 C，除非万不得已不碰 B。**

路线 C 的现成脚本：AURKNIX 镜像自带 **`MOD_TOOLS/Install AURKNIX to EMMC.sh`**（来源：本地已存的 `AveyondFly/distribution_rocknix@next` 用户手册 §8.1，脚本假定 TF=`/dev/mmcblk1`、eMMC=`/dev/mmcblk0`，**必须先确认机器上这两个块设备对应关系**，全程插电不断电）。
ArkOS4Clone 这边要留意口径冲突：上游 Wiki 的 Known Limitations 写 **"eMMC installation not yet supported"**，但 20261008 的 Release 说明写 **"Added support for writing dArkOS4Clone to eMMC"**——**只有 dArkOS4Clone 分支能写 eMMC，ArkOS4Clone 不能**，Wiki 那句话相对老镜像仍然成立。（两个来源：`arkos4clone.wiki/Installation.md`、`gh api repos/lcdyk0517/arkos4clone/releases/tags/20261008` 的 body，本轮 2026-11-05 都重新拉过。）

## 一、动手前的 6 项检查（缺一项目测翻车率明显上升）

1. **备份原厂卡**。把出厂那张 TF 卡整卡读回一个文件存好（Rufus/USB Image Tool 都有 Backup/Save 功能，`dd` 也行）。**原厂卡是唯一的 dtb 与屏幕初始化参数来源**——本机库里已经有多条"原厂 dtb 丢了以后屏幕点不亮、只能逐个试"的记录（`机型固件/R36S/00-R36S完全指南.md` 第二节的 FAQ 就是这个）。
2. **确认 SoC，不是确认外观名字**。RK3326 / RK3562 / RK3566 / H700 的镜像**互不通用**。AURKNIX 手册 §3.2 原文：**"RK3566 与 RK3326 镜像相互独立：不要使用 RK3326 包刷 RK3566 机器"**；§3.4 又补一条：RK356X（5.10 BSP 内核）与主线 RK3566（6.x 内核）的更新包**也不通用**。怎么查芯片：`05-硬件与机型资料/` 的机型对照表 + `panel_specs.tsv`。
3. **插电**。ArkOS4Clone 的机型说明原文：**"Please connect the charger when powering on. If it is an original machine, please ensure the battery voltage is not lower than 3.3V before powering on, otherwise it may fail to boot."**（来源：本地 `Changelog.md`）；但 dArkOSRE 那边反过来要求**首次开机不要插电源**（来源：`上游wiki/dArkOSRE-R36/Firmware-Installation.md` 的 CAUTION）。**这两条不矛盾**：装系统与首次扩容的时机不同——**写卡、进刷机模式全程插电；装完系统后那次首次开机按你要刷的那个系统的原文来**。不清楚就按"插电"办，断电变砖的概率远大于插电。
4. **卡要好**。R36S 对卡极敏感，上游在 `Firmware-Installation.md` 开头专门挂了一篇《为什么一张好 SD 卡很重要》。**AURKNIX 20261008 之前的 ArkOS4Clone 也修过"部分 SD 卡解压 roms.tar 时卡住"**（Release body 原文），说明"卡的问题"在这个生态里是真实存在的一类 bug，不是推诿。建议三星/闪迪 64–128GB，**别上 256GB+ 和杂牌**。
5. **第一次动手只准备一张卡**。装系统时**把第二张卡取出来**，装完再插回去（dArkOSRE 原文要求；arkos4clone 也有"ES 里切到卡 2 会导致端口崩溃"的历史 bug，修复于 20260927，但依赖仍在卡 1）。
6. **记下你现在能开机的 dtb 名字**。BOOT 分区里那个 `.dtb` 文件名（或原厂卡 dtb 目录）就是你机器的身份证。丢了它，后面只能靠试。

## 二、下载与校验：只认官方域名 + 逐字节哈希

**只从这些地方拿东西**（域名写清楚，防"下载站二次打包"）：

| 内容 | 官方地址 | 本轮实测 |
|---|---|---|
| ArkOS4Clone / dArkOS4Clone 镜像 | `github.com/lcdyk0517/arkos4clone/releases` | 20261008 三个分卷全部按 GitHub `digest` 校验通过（见台账） |
| ROCKNIX 主线镜像 | `github.com/ROCKNIX/distribution/releases` | 20261101 是最新 |
| AURKNIX（含稀范/克隆机的 ROCKNIX 改版）正式版 | `github.com/AveyondFly/distribution_rocknix/releases` | 最新 tag 20260809 |
| AURKNIX nightly | `github.com/AveyondFly/distribution-nightly/releases` | 最新 nightly-20260918 |
| AURKNIX **CI 产物**（比 release 新，含最新机型适配） | `github.com/AveyondFly/distribution_rocknix/actions` → 某次成功 Build → Artifacts | 20261021 那次有 12 个产物；**要登录 GitHub 才能下，且产物会过期** |
| 稀范 XiFan 原厂镜像与刷工具 | `github.com/handheld520/*` 各机型仓 + `handheld520.github.io` 机型页（页内同时给百度网盘 `?pwd=XFXF`） | R36MAX2/XF45V 已按 digest 校验通过 |
| 校验工具本身（Rufus/USB Image Tool 等） | 各自的官方域，见 `09-刷机工具/README.md` | — |

**校验怎么做**（Windows 自带，不用装东西）：

```powershell
# 单个文件
certutil -hashfile "F:\开源掌机教程\02-模拟器库\已clone仓库\系统镜像\ArkOS4Clone-20261008.img.xz.7z.001" SHA256
# 或者 PowerShell
Get-FileHash -Algorithm SHA256 -Path "…\xxx.img.gz"
```

**跟谁比**：GitHub 每个 Release 资产都带一个 `digest` 字段，形如 `sha256:ccf03973…`，那就是作者发布的官方哈希（本项目台账里所有 `来源=GitHub digest` 的条目都是这么来的）。`.sha256` 附属文件也是同一份值。

**三条踩过的坑**：
1. **别手抄哈希**。本项目曾经把一个 Rufus 的 digest 手抄错一位，跑出 `BADHASH` 白紧张一场——现在台账脚本一律**从 API 直接取 digest 再比对**，人不碰数字。
2. **`http=200` 不等于拿到完整文件**。curl 被超时掐断时，`-w` 里照样能打 200，半截文件看着像"成功"。所以校验必须**同时比字节数和哈希**——本项目的下载脚本现在两道都查。
3. **单次 404 什么都证明不了**。同一个 URL 会瞬态 404/000；判可达性至少重试两三次，并换抓取路径。

**分卷包怎么合**：ArkOS4Clone / dArkOSen 的 Release 都是 `.img.xz.7z.001/002/003`（7-Zip 卷切分）。**7-Zip 会自己找后续卷；命令行可以直接喂第一个卷**：

```bat
"C:\Users\<你>\.qoder\bin\7zr.exe" x -y -o. "ArkOS4Clone-20261008.img.xz.7z.001"
```

解出来是 `.img.xz`，写卡前还要再解一层 xz：**`xz -d 文件.img.xz`**（或 7-Zip 解压）得到 `.img` 再写，这条对所有工具都成立、也最容易核对哈希。
> 我没有实测过 Rufus 直接吃 `.xz`/`.gz` 的行为，所以这里不写成"可以"；本地 `.img.xz` 与解出的 `.img` 的字节数、SHA256 都记在系统镜像台账里，以解出的 `.img` 为准来写最稳。
**不要用 WinRAR 解镜像包**（dArkOS 上游原文点名它会解坏）。

## 三、写卡（路线 A 的完整步骤）

本地已经把工具都下好了，清单和哈希在 **[09-刷机工具/README.md](file:///F:/%E5%BC%80%E6%BA%90%E6%8E%8C%E6%9C%BA%E6%95%99%E7%A8%8B/09-%E5%88%B7%E6%9C%BA%E5%B7%A5%E5%85%B7/README.md)**。选型：

| 工具 | 用在哪 | 备注 |
|---|---|---|
| **Rufus（便携版）** | 首选。写镜像时**必须选"DD 模式"** | 选"可启动 ISO"模式就废了 |
| **USB Image Tool** | dArkOS 系作者首选，Restore 功能最直白 | alexpage.de 官方 zip |
| **Raspberry Pi Imager** | 想顺便校验写入 | 它自带校验，慢一点 |
| **balenaEtcher** | ⚠️ dArkOS 上游明写**大量用户报失败，不要用**；ROCKNIX/AURKNIX 官方文档却把它列在推荐第一位 | 结论：**能不用就不用**。已下好备用，哈希在台账里 |
| ~~Windows 自带的"格式化"~~ | **绝对不要点** | 见下面第 5 步 |

**步骤**：

1. 插卡，记下盘符/盘号。**看清楚是哪个盘**——写镜像是"整盘覆盖"，选错盘就是把 U 盘或硬盘抹了。
2. 解出 `.img`（`.gz` 用 `gunzip`、`.xz` 用 `xz -d`、7z 卷用 7-Zip；先解再写，别赌工具的自动解压）。
3. **先校验哈希**（第二节），再写。这一步挡掉的是"下载截断导致的玄学黑屏"，成本几分钟，值得。
4. 工具里选镜像 → 选目标盘 → **DD/裸写入** → 开始。1.5–2GB 的镜像在 USB3 上一般 3–8 分钟。
5. 写完后 Windows 会弹窗"**需要格式化磁盘**"——**点取消**。那是因为它读不懂 ext4 分区，不是卡坏了。**千万别点格式化，也别在资源管理器里"修复"那个分区。**
6. 弹出前用工具的"安全删除"，别直接拔（写到一半拔=卡上系统残废）。

**镜像里的分区长什么样**（2026-11-05 实测：拿 `_工具脚本\列出BOOT分区.py` 直接解析整条 `ArkOS4Clone-20261008.img`（12,884,901,888 B）的 MBR 与 FAT32 目录项得到，与 20260930 版布局一致）：

| 分区 | 类型 | 起始偏移 | 容量 | 作用 |
|---|---|---|---|---|
| p1 | 0x0B FAT32 | LBA 32768（16 MB） | 256 MB | **BOOT**，Windows 能看到的就是它 |
| p2 | 0x83 Linux | 285,212,672 B | 11.00 GB | storage（ext4，首次开机会扩到整卡剩余） |
| p3 | 0x07 | 12,096,372,736 B | 0.73 GB | ROM 分区（ArkOS 侧标签 `EASYROMS`） |

**前 16MB 是 U-Boot/引导区**，所以 Windows 看不到、也不该动。

## 四、最关键的一步：告诉系统"我是哪台机器"（dtb / boot.ini）

**RK3326/RK3562 这一系刷完黑屏，绝大多数不是镜像坏，是设备树（dtb）选错**——背光亮、logo 可能闪过、然后黑屏，就是这个。三套系统三种做法，**别混用**：

### 4.1 ArkOS4Clone / dArkOS4Clone：BOOT 分区里的 `dtb_selector`

上游 Wiki `Installation.md` 的 Usage 四步原文（已复核）：

1. 下载 **ArkOS** release 镜像；2. 刷到 SD 卡；3. **在 Windows 上运行 `dtb_selector.exe` 选你的设备**；4. 提示时选电池驱动版本（**Original** 或 **arkos4clone_fix**）；5. 重启机器。

`dtb_selector_win32.exe` **就在刷好的卡的 BOOT 分区里**，不用另外下载。本轮实测证据：把 `ArkOS4Clone-20261008` 的三个分卷全量解出、再解 xz 得到 12,884,901,888 B（正好 12 GiB）的 `.img`，用 `_工具脚本/列出BOOT分区.py` 直接读它的第 1 分区（FAT32）根目录，得到：

```
dtb_selector_win32.exe    5,560,320 B      dtb_selector_macos      11,275,970 B
dtb_selector_linux32      5,410,968 B      dtb_selector_linuxarm    5,505,176 B
uInitrd                  13,194,771 B      clone.sh                    19,491 B
expandtoexfat.sh              6,311 B      fstab.exfat                    269 B      firstboot.sh    53 B
consoles/  <目录>          boot  <目录>     System Volume Information  <目录>
```

**注意这张清单里没有 `boot.ini`、没有 `Image`、没有任何 `.dtb`，也没有 `logo.bmp`**——这不是镜像坏了。全新卡刷完，BOOT 根目录就是空的（只有可选器和 `consoles/`），**必须**先跑一次 `dtb_selector`（或按下面"手动做法"自己复制）把这四样东西摆进根目录，否则机器无从引导。很多人"刷完黑屏"就卡在这一步：以为写完卡就完事了。

电池驱动那一格为什么重要：`arkos4clone_fix` 是本项目的自研电池驱动，**充电时电量显示更准、放电曲线更平滑**，寄存器已与原厂驱动对齐、老化信息存 `/var/lib`（来源：Changelog 20260805/20260825 段落）。选错的表现是电量数字不动或满充后喇叭有干扰声（这两个 bug 都在 20260805 修过）。

**非 Windows 的手动做法**（Wiki "Manual Configuration" 原文）：挂载 BOOT 分区 → 把 `consoles/<机型>/` 里的 `boot.ini` 和两个 `.dtb` 复制到根目录 → 按电池驱动选 `consoles/kernel/original/Image` 或 `consoles/kernel/arkos4clone_fix/Image` 复制过去 → 把 `consoles/logo/<分辨率>/logo.bmp` 复制到根目录 → 安全弹出、插机、重启。
**分辨率档要选对**：640×480 的机器用 `logo/480P/`，1024×768 的（XF45V/R36Max2/RF45H 等）用 `logo/768P/`——这就是 `ExtraSources` 字段的意思。

`boot.ini` 里能看到什么（以 `consoles/r36max2/boot.ini` 为例，本轮拉到原文）：

```
setenv bootargs "root=/dev/mmcblk0p2 … fbcon=rotate:0 … max_cpufreq=1296 boot_cpufreq=1248 max_gpufreq=520 max_ddrfreq=666"
load mmc 1:1 ${dtb_loadaddr} rk3326-r36max2-linux.dtb
```

即：**卡 1 的 1 分区引导、根文件系统在第 2 分区、屏幕不旋转、CPU/GPU/DDR 频率上限都写在这里**。ES 里那些"CPU/GPU/DMC 频率调节""旋转屏幕"的开关，最终就是改这个文件。

### 4.2 dArkOS / dArkOSRE / dArkOSen：`SELECT MODEL`

卡写好后，Windows 下双击 BOOT 分区里的 **`SELECT MODEL`** 脚本 → 输入板型编号 → `Y` 确认 → 退出。macOS/Linux 则手动：删掉 BOOT 根目录所有 `.dtb`，再从对应目录复制正确的那一个（完整路径表见 `05-硬件与机型资料/devices.json` 的 `dtb_path` 字段）。细节在 `R36S/00-R36S完全指南.md` 第四节。

### 4.3 ROCKNIX / AURKNIX：镜像分档 + `dtbselect`

**第一层：镜像文件名的后缀就是硬件档，选错后缀根本没得救。** 主线 ROCKNIX 官方 20261101 的发布表逐条列了谁用哪个（本轮原文摘录）：

- `ROCKNIX-RK3326.aarch64-20261101-a.img.gz` → **Anbernic RG351M/RG351V、GameConsole R33S、GameConsole R36S、MagicX XU10、Odroid Go2/Go2 V11/Go3、Powkiddy RGB10**
- `ROCKNIX-RK3326.aarch64-20261101-b.img.gz` → RGB10X、RGB20S、XU Mini M、EE Clone、BatleXP G350、GKD Pixel2

所以 **R36S 用 `-a`**。AURKNIX 手册 §3.2 另说 RK3566 有 `-Generic`（运行时从 FAT 分区多 DTB 里选，对应 `FDTDIR`）和 `-Specific`（单一固定 DTB，对应 `FDT` 一行）两种；§3.4 说 RK356X 发布包含 **RK3562 / RK3566-Generic / RK3566-Specific** 三套安装镜像、共用一个更新包。

**第二层：`dtbselect` 选具体机器。** RK3562 这类必须做，AURKNIX 手册 §3.4 原文：

> RK3562 机型使用 `*-RK3562.img.gz`。写卡后，在启动分区运行 `/flash/dtbselect`（Linux）或 **`DtbselectWin64.exe`（Windows）**，选择与机器完全一致的设备树。
> Xifan：**NGP45H、XF55H** — 选择与机器型号同名的设备项。

**别把这一层理解成"只有 RK3562 才要选设备树"。** 本轮我解析了 `AURKNIX-RK3326.aarch64-20261021.img.gz` 的 BOOT 分区:
它的 FAT 根目录**平铺 78 个 `.dtb`**,里面有 `rk3326-xifan-xf45v.dtb`、`rk3326-xifan-r36max2.dtb` 等 XiFan 全系,
`dtb_selector.py` 的表里也逐条写着 `" XF45V": DtbEntry("rk3326-xifan-xf45v.dtb", 202)` / `" R36Max2": DtbEntry(..., 202)`。
**那个 202 不是版本号,也不是 FAT 属性**——我从读它的代码里查清了:`DtbEntry` 的第二个字段名叫 `tty`,
`_parse_tty_spec()` 遇到整数就走 `_to_tty_name(v) → f"ttyS{v % 100}"`,所以 **202 → 串口控制台 `ttyS2`、101 → `ttyS1`**,
它和 `extlinux.conf` 里 `console=ttyS2,1500000 … systemd.debug_shell=ttyS2` 是同一条链(选完机型会改写 APPEND 行的 console)。所以 **AURKNIX 的 RK3326 分支同样要跑 `DtbselectWin64.exe`**;
它和 ArkOS4Clone 的区别只是布局:ArkOS4Clone 把 dtb 藏在 `consoles/<机型>/` 里、写的是 U-Boot 的 `boot.ini`,
AURKNIX/ROCKNIX 把 dtb 平铺在 BOOT 根、改的是 `extlinux.conf` 的 `FDT` 行(由 `patch_fdt_line()` 重写第一条未注释的 FDT)。
过程与教训记在 `02-模拟器库/已clone仓库/系统镜像/README.md` §3.4——判"某个固件支不支持某机型"必须**解析镜像里的 FAT 目录 + 读选择器的表**,只看 release 说明会得出错结论(我自己本轮就错过一次并已更正)。

**第三层：面板/按键的补丁用 overlay。** 本地已存的 Windows 版 `dtbselect` 自带的模板文件说明了它到底改什么（`F:\开源掌机教程\09-刷机工具\dtbselect\extracted3326\inner\config\extlinux.conf`）：

```
LABEL ROCKNIX
  LINUX /KERNEL
  FDTDIR /
  FDT /my.dtb
  FDTOVERLAYS /overlays/mipi-panel.dtbo
  APPEND boot=${partition_boot} disk=${partition_storage} … uboot.hwid_adc=${hwid_adc}
```

`FDTDIR`（多 dtb 目录）与 `FDT`（单一 dtb）二选一，正是 Generic/Specific 两种镜像的差别；`mipi-panel.dtbo` 是屏幕面板叠加层；`hwid_adc` 是"用摇杆 ADC 复用出来的键来区分 clone 型号"那个机制（Changelog 20260915 第 3 条）。

## 五、首次开机

- **别期待"秒开"**。首次启动要解压 ROM 模板 + 扩容分区，**2–3 分钟**很正常；进度条/黑屏一段时间不代表失败。**全程不要断电、不要按重启**。
- **黑屏三种情况的分流**（Changelog 20260825 的 FAQ 原文）：
  1. **logo 正常显示后才黑** → dtb 选对了，问题在系统/卡；**换一张卡再试**。
  2. **logo 都出来了但背光不亮** → 长按电源或拔电池，**接上充电器**再开机。
  3. **没有 logo 直接黑屏** → 用 dtb 选择器重选机型。
- **不知道自己是哪种面板**：只能逐个试（试一个必须长断电/重插电池再试下一个），试到出 logo 为止；这只保证屏幕参数兼容，**原厂初始化参数拿不回来**（上游原话：这类机器请不要提 Issue）。
- 识别工具（本轮重测可达性）：
  - `https://r36s.dpdns.org/dtbTools.html` → **200，7,044 B**（判机器型号）
  - `https://r36s.dpdns.org/tools/dtb-tools.html` → **200，68,160 B**（改摇杆轴/按键/电池容量/刷新率并生成新 dtb）
  - `https://lcdyk0517.github.io/…` 同样两个路径现在都回 **301**（跳上面那个域）。
  - ⚠️ 第二个工具的上游原文注明：**只支持 (d)ArkOS4Clone 生成的 dtb**，原厂 dtb 和其它发行版的 dtb 丢进去不兼容。

## 六、eMMC 线刷（路线 B）：唯一一份厂商原文口径

**只有原厂文档给了这台机器的进刷机模式按键组合**，这段是从稀范自己那份 `刷工具及教程` 里逐字摘出来的（包已下在 `09-刷机工具/`，RAR 里是 `FactoryTool_v1.81` + `RK-USB-DriverAssitant_v5.1.1`）：

> **关机状态下**：同时按住 **10 秒开机键和音量+**，进入刷机状态，刷机成功拔出，**按一下重启键**，然后按开机键开机。
> **开机状态下**：先按一下重启键，然后**按住音量+**，十秒进入刷机状态……
> **先安装驱动**（DriverAssistant），**然后打开 FactonryTool**（原文拼写如此，即 FactoryTool）。

配套工具与获取途径（本轮实测）：

| 工具 | 官方来源 | 版本 |
|---|---|---|
| FactoryTool | 稀范 `Flashing.software.rar`（GitHub release 直链已下，sha256 `930ed905…`） | v1.81 |
| DriverAssistant | 同上 RAR 内 | v5.1.1 |
| RKDevTool（替代方案） | `github.com/themacobs/…`/官方分发点，本项目拿的是 v0.16.0 x64 安装包 | 见 `09-刷机工具/README.md` |
| Rockchip 官方工具镜像 | `https://dl.radxa.com/tools/windows/`：`RKDevTool_Release.zip`(v3.37)、`DriverAssitant.zip`(v5.14)、`RK_BatchTool_V1.7.zip`、`SDDiskTool v1.74`、`PhoenixCard v4.3.2` | 本轮**只核对了 URL，未下载**（未实测） |

**线刷的硬规矩**：
1. 先装驱动再插线；设备管理器里要看到 `Rockchip USB Driver`/`LOADER`/`MASKROM` 之类的条目。**没识别到设备就点"刷机"= 什么都没发生**（工具会显示"找到设备 One"，没有就是没进模式）。
2. **原厂 eMMC 里的系统一旦被覆盖就回不来**。原厂在 GitHub 发的 eMMC 镜像可以刷回去（本项目已下：`grc803_r36max2_es_r_emmc_20260714.img`、`grc803_xf45v_es_r_emmc_20260714.img`，两个都按 GitHub digest 校验过），但**"原厂发布版本"≠"你出厂那份"**，出厂带的定制内容会丢。
3. 全程插电、别拔线、别睡眠电脑（把 Windows 电源计划临时设成不睡眠；远程/后台跑的时候注意灭屏不等于睡眠，见 `powercfg` 那条坑）。
4. **能走 A/C 就不要走 B**。B 是给"没得选"的机器用的。

## 七、装完之后：游戏放哪、卡怎么用满

- **双卡布局（R36S 这类两个卡槽的）**：卡 1 = 系统（ROM 分区标签 `EASYROMS`）；卡 2 = 游戏，**exFAT**，卷标起一个**独特名字**（`ROMS2` 之类），**别再叫 EASYROMS**——重名会主题丢失/启动异常。切卡：ES 里 `START → Options → Advanced → Switch to SD2 for Roms`。
- **AURKNIX 的分区自定义**（很有用，来源：用户手册 §4）：写卡后在能被挂成 `/flash` 的 FAT 分区**根目录**建一个空文件，文件名严格写成 **`resize_storage_<整数>G`**（如 `resize_storage_32G`），首次开机就会把 ext4 `/storage` 只扩到该上限，**剩余空间新建 exFAT 的 `GAMES` 分区**给 Windows/macOS 直接拷游戏。三个前提记牢：①**必须在第一次正常进系统并完成初始化之前**放好这个文件，已经初始化过会拒绝再扩容；②卡的总容量必须**大于**你设的数；③日志在 `/flash/fs-resize.log`，失败会回退成"storage 扩到整盘剩余"。
- **升级**：AURKNIX/ROCKNIX 用 `AURKNIX-<机型>.aarch64-<日期>.tar` 做 OTA（系统设置里在线更新，或把 tar 丢进 `/storage/.update/`；`/storage` 空间不足时可放 `/storage/roms/.update/` 再跑 `MOD_TOOLS/Offline Upgrade`，见手册 §10）。ArkOS4Clone 从 20261008 起 ES 里能直接在线更新，离线更新走 `lcdyk0517/arkos4clone-updates` 仓库。
