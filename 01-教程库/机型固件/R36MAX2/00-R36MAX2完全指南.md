## 二、怎么确认"我这台就是 R36MAX2"(以及为什么不能照抄 R36S 教程)

三条可复核证据:

1. **上游支持表**:`lcdyk0517/arkos4clone` 的 `Changelog.md:218` 把 XiFan 一系逐名列出,其中包含 `R36MAX2`:
   `XiFan[Mymini,Mini40,R36Max,R36Pro,XF35H,RF35H,XF40H,RF40H,DC35V,XF40V,DC40V,XF28,R36MAX2,XF45V,DC45V,RF45V]`
2. **机型目录真实存在**:仓库里有 `boot/dArkOS/consoles/r36max2/`,内含 `boot.ini` + `rk3326-r36max2-linux.dtb`。
   本轮拉到的 `boot.ini` 原文关键行(本地存档 `_scratch/ak_r36max2_boot.ini`):
   ```
   setenv bootargs "root=/dev/mmcblk0p2 rootwait rw … fbcon=rotate:0 … max_cpufreq=1296 boot_cpufreq=1248 max_gpufreq=520 max_ddrfreq=666"
   load mmc 1:1 ${loadaddr} Image
   load mmc 1:1 ${initrd_loadaddr} uInitrd
   load mmc 1:1 ${dtb_loadaddr} rk3326-r36max2-linux.dtb
   ```
   读法:**从卡 1 的第 1 分区引导、根文件系统落在 `mmcblk0p2`、屏幕不旋转(横屏)、CPU/GPU/DDR 上限写死在这里**。
3. **面板反查**:直接解析镜像自带的那块 dtb(不是抄商品页),结果落在
   [`../../../05-硬件与机型资料/panel_specs.tsv`](../../../05-硬件与机型资料/panel_specs.tsv):
   `r36max2 → 1024×768, clk 62MHz, DSI 4 lane, joystick=dual, hotkey=happy5(有 FN 键用 FN 当热键), rotation=0, led=ws2812, volume=adc`。
   同档 1024×768 的机型共 14 条:`dc45v go2 h7 r36hpromax r36max2 r36ultrax r40xx r40xxpromax r45h r46h rf45h rf45v xf45v`(+1 条 R46H 重复条目)。

⚠️ 上面那张表里 `w_mm / h_mm / diag_in` 三列**整列不可信**(厂商把 153×85 复制粘贴到了整个 XiFan 系),寸数自己卡尺量。

**为什么不能照抄 R36S 教程**:R36S 是 640×480,你的是 1024×768 = **2.56 倍像素**。
后果:① 640×480 主题/启动 logo 会糊或留黑边,要用 `logo/768P/` 那一档;② 3D 平台(PS1/N64/DC/PSP)帧率比 R36S 更吃紧;
③ PortMaster 那边你的机器会被识别成 `hires`(≥960 宽),不是 `r36s`。详细解释在 [`../XiFan_XF45V/00-XF45V完全指南.md`](../XiFan_XF45V/00-XF45V完全指南.md) 第三节,那篇讲的是同分辨率的另一台机器,这些部分可以直接借用。

**给你的默认答案:ArkOS4Clone 20261008。**

## 四、R36MAX2 刷机:照这个顺序做

前置阅读:`../00-刷机通用流程与工具.md`(校验、写卡、进 MASKROM 的通用规矩都在那儿)。下面是本机特有的部分。

### 路线 A:TF 卡刷 ArkOS4Clone(推荐先做这个,拔卡就能回原厂)

1. **备份原厂卡 / 记原厂系统**。若系统装在内建存储,先按第五节把 eMMC 内容心里有数(至少知道自己是哪个批次)。
2. 解包:三个分卷 `ArkOS4Clone-20261008.img.xz.7z.001/002/003` 放同一目录,用 **7-Zip 右键 Extract**(不要 WinRAR,不要只解 001)。
   得到 `ArkOS4Clone-20261008.img.xz`(4,382,690,752 B),再解一层得到 `ArkOS4Clone-20261008.img` = **12,884,901,888 B(正好 12 GiB)**。
   ⇒ **卡最小 16GB,建议 32–128GB 三星/闪迪**;256GB+ 与杂牌卡在上游 issue 里反复出事。
3. **校验哈希再写卡**(本机已实测值见 [`../../../02-模拟器库/已clone仓库/系统镜像/README.md`](../../../02-模拟器库/已clone仓库/系统镜像/README.md))。
4. 写卡:Rufus(选镜像后必须点 **DD 模式**)/ USB Image Tool / rpi-imager。Windows 弹"需要格式化磁盘"时**点取消**。
5. 写完后在 Windows 打开 BOOT 分区(256MB 那个 FAT32),**双击 `dtb_selector_win32.exe`**:
   - 选机型:**R36 Max 2**(工具会往 BOOT 根目录摆 `boot.ini`、`rk3326-r36max2-linux.dtb`、`logo.bmp`);
   - 选电池驱动:**Original** 或 **arkos4clone_fix**(见本节末)。
6. 插卡、**首次开机不要插电源/充电器**(上游 CAUTION,且本机有过"只认外接电"的历史 issue,冷启动行为要单独验)、**不要插第二张卡**。
7. 首次启动 2–3 分钟(它在解 roms.tar 和扩容),期间别断电;进 EmulationStation 即成功。

**本轮实测的 BOOT 根目录清单**(把 20261008 完整解出后读 FAT32 第 1 分区得到,`_工具脚本/列出BOOT分区.py`):

```
dtb_selector_win32.exe   5,560,320 B   dtb_selector_macos     11,275,970 B
dtb_selector_linux32     5,410,968 B   dtb_selector_linuxarm   5,505,176 B
uInitrd                 13,194,771 B   clone.sh                   19,491 B
expandtoexfat.sh             6,311 B   fstab.exfat                   269 B   firstboot.sh  53 B
consoles/ <目录>   boot <目录>   System Volume Information <目录>
```

**看清楚了:根目录里没有 `boot.ini`、没有 `Image`、没有 `.dtb`、没有 `logo.bmp`。** 全新卡刷完就是这副样子,第 5 步不做,机器必然黑屏——这是这台机器(以及整个 ArkOS4Clone 生态)最常见的"假砖"。

分区表实测(同一个 img):`p1 FAT32 起始 LBA 32768 / 256MB`,`p2 Linux 0x83 / 11.00GB`,`p3 0x07 / 0.73GB`;前 16MB 是 U-Boot 等裸区。

**电池驱动那一格怎么选**:先选 **arkos4clone_fix**(本项目自研,充电时电量更准、放电曲线更平滑);
如果你机器出现电量数字不动、满充后喇叭干扰声这类历史 bug 表现,再回退 **Original**。两个 `Image` 的内容差异我早前用 `cmp` 真验过,不是摆设。

### 路线 B:写进内置 eMMC

**口径冲突,先说清楚**:
- 上游 Wiki `Installation.md` 的 Known Limitations 原文仍写 **"eMMC installation not yet supported — Currently only booting from SD card is available"**;
- 但 **Release 20261008 正文**原文写 **"Added support for writing dArkOS4Clone to eMMC. Thanks to qzydustin."**

两者不一致 ⇒ 把 Wiki 当作"滞后文档",但**不要把 eMMC 刷写当成零风险操作**。真要走 eMMC,优先用**厂家自己的 eMMC 包 + 厂家 FactoryTool**(第五节),那是唯一有官方图文教程的路线。

### 路线 C:回到厂家官方 EmuELEC

`grc803_r36max2-ee-r-TF-20260207.img.gz`(832,575,444 B)是 TF 卡刷包,直接写卡即可,不选 dtb(原厂系统自带正确面板配置)。
来源:`https://github.com/handheld520/XiFan-R36MAX-2/releases` tag `20260316`(正文 "Add R36MAX2 TF");更早的 tag `20260201` 里是 `...TF-20260131-1` 版本,哈希不同,别混。

## 五、有 eMMC 的机器:官方线刷口径(唯一的官方说法)

厂家包 `Flash-Guide.tool.rar` 里的 `EMMC升级刷机教程.doc` 正文(antiword 抽取,原话):

> 先安装驱动 …… 然后打开 FactonryTool(原文如此,即 FactoryTool)……
> 机器链接 OTG 插口,USB 连接电脑,
> **关机状态下**:同时按住 10 秒开机键和音量+,进入刷机状态,刷机成功拔出,按一下重启键,然后按开机键开机。
> **开机状态下**:先按一下重启键,然后按住音量+,十秒进入刷机状态,刷机成功拔出,按一下重启键,然后按开机键开机。

工具已落地本地:`09-刷机工具/Flash-Guide.tool.rar`(13,878,956 B,digest 对上)内含 `FactoryTool_v1.81` + `RK-USB-DriverAssitant_v5.1.1` + 教程 doc;台账见 `09-刷机工具/README.md` 第二节。

**风险提醒**:线刷会重写内置存储,失败后需要短接/MASKROM 级手段才能救;`音量+ 与 开机键同按 10 秒` 是官方给的进刷机态方法,比任何"拆机短接"安全。第一次做请只用厂家官方 `grc803_r36max2_es_r_emmc_20260714.img`,别拿第三方镜像练手。

## 六、R36MAX2 的已知问题(逐条附可复核出处)

## 七、刷完之后:游戏、BIOS、Ports

- **ROM 目录/扩展名/BIOS 对照表**:见 [`../../R36S/00-R36S完全指南.md`](../../R36S/00-R36S完全指南.md) 第六节。ArkOS 系目录名通用(`gb/gbc/gba/nes/snes/megadrive/psx/n64/nds/psp/…`),R36MAX2 不需要改;但 **AURKNIX 的路径是 `/storage/roms/<系统>`**,和 ArkOS 的 `/roms/<系统>` 不是一套,别抄错。
- **双卡布局**:R36MAX2 是双 TF 槽。ArkOS4Clone 的 BOOT 分区里带着 `expandtoexfat.sh`、`fstab.exfat`、`clone.sh` 三个脚本(字节数见第四节)——用途就是"把资料区扩成 exFAT / 双卡挂载"。具体操作与卡 2 卷标命名的坑见通用文档第七节。
- **PortMaster**:ArkOS4Clone 20260930 起在系统里带 `Install.PortMaster`,**装完必须先手动运行一次**,否则 PortMaster 打不开(Release 20260930 正文原话)。设备指认:你的机器是 1024×768,按 `hires` 走,别照 640×480 的 r36s 端口清单硬套;合法可下载池的统计口径见 `04-游戏资源库/公版与开源游戏/PortMaster移植游戏指南.md`。
- **能玩什么**:GB/GBC/GBA/FC/SFC/MD/PCE/街机满速;PS1 良好(装 BIOS 更稳);N64/PSP/DC 因为像素是 R36S 的 2.56 倍,**只会比 R36S 更吃力**,先看逐游戏实测表 `02-模拟器库/已clone仓库/R36S专用/R36S-Game-Compatibility-Lists`;GC/Wii/PS2/3DS **不要期待**。
