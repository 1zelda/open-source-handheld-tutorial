# C++ 路线:从"看得懂模拟器源码"到"自己做游戏"

这份是**学习路径 + 本地可参照的代码**,不是编译手册。具体编译命令一律以上游仓库 README 为准(版本变动快,我写死命令容易坑你)。

## 为什么开源掌机这一圈本质上是 C++/C 的世界

掌机上你用的每一层都是 C/C++:
- **模拟器核心**:几乎所有 libretro core 是 C(gambatte、mgba、pcsx_rearmed、Genesis-Plus-GX),现代主机级模拟器是 C++(DuckStation、RPCS3、yuzu 系、PPSSPP)。
- **前端**:RetroArch / EmulationStation 是 C++。
- **掌机自制游戏**:GB/GBA 用 gbdk(C)或 butano(C++)。

所以学 C++ 走"掌机/模拟器"这条线是很务实的:目标具体、代码量可控、能立刻看到屏幕上有东西在动。

## 阶段一:先当使用者(1–2 天)
目标:不改代码,但能看懂配置项在说什么。
- 读本库 `02-模拟器库/模拟器与核心/README.md`,知道 core 与前端的关系。
- 在电脑上装 RetroArch,把 `gambatte`、`mgba` 两个核心跑起来。
- 对照 `03-BIOS库/00-BIOS需求总表.md` 理解"为什么 PS1 需要 BIOS 而 GBC 不需要"。

## 阶段二:读懂一个最简单的核心 —— Game Boy(1 周)
本地参照:`02-模拟器库/模拟器与核心/gambatte-libretro`(约 7MB,代码规模适合通读)。

读的时候按这条线走,不要从第一行往下硬啃:
1. **入口**:libretro 核心必须导出几个约定函数 —— `retro_init`、`retro_run`、`retro_set_controller_port_device`、`retro_serialize`。找到 `retro_run`,它就是"每帧调用一次的循环体"。
2. **一帧里发生了什么**:CPU 跑若干指令 → LCD 控制器扫描线推进 → 产生中断(VBlank/HBlank)→ 帧结束时把 framebuffer 交给前端(`retro_video_refresh_t`)。
3. **内存映射**:GB 的 0x0000–0x3FFF 是 ROM bank0,0x8000 是 VRAM,0xFE00 是 OAM(精灵表)。看到魔数地址就知道在访问什么硬件。
4. **PPU 与精灵**:GB 每帧最多 40 个精灵、每行最多 32 像素宽精灵,超出会消失——这类"硬件限制"就是当年游戏 bug 的来源,也是模拟器要精确模拟的地方。

对应练习(不看答案):在代码里找出 `joypad` 读取在哪、VBlank 中断在哪触发。

## 阶段三:写一个 CHIP-8 模拟器(1–2 周,最关键的一步)
CHIP-8 是"最小可完成的学习版 CPU + 屏幕 + 键盘 + 蜂鸣器"平台,指令集只有 35 条左右,**一周内能写完并看到《Pong》跑起来**。这是从"读代码"跨到"写模拟器"的分界线。

必须自己实现的 5 个模块:
| 模块 | 要点 | 常见坑 |
|---|---|---|
| 内存 4KB | `uint8_t memory[4096]`,程序从 0x200 开始加载 | 忘了 0x000 区放字体精灵 |
| 寄存器 | 16 个 V 寄存器 + I(地址寄存器)+ 定时器 DT/ST | DT 和 ST 别混 |
| 取指执行 | 每次取 2 字节大端,`switch(op >> 12)` 分派 | 大端读取写成小端 → 全盘乱码 |
| 屏幕 | 64×32 单色,`FXXY` 绘制是 **XOR**(重复绘制=擦除) | 把 XOR 写成赋值 → 精灵闪烁异常 |
| 主循环 | 每帧:处理输入 → 执行若干指令 → 渲染 → DT 递减 | 没有节流就是全速跑,音乐和游戏速度飞起 |

调试工具:先用一个 CHIP-8 测试 ROM(如 `OBCHP Test`)逐条指令校验,比拿游戏猜快 10 倍。

## 阶段四:进入 C++ 现代模拟器代码(2–4 周)
本地参照(都在 `已clone仓库/模拟器与核心/`):
- **PPSSPP**(C++):看它如何做 JIT 和 GPU 后端抽象。重点目录是 UI/Emu 划分,架构非常干净,适合学"大型 C++ 项目怎么分层"。
- **RetroArch**(C):看 `retroarch.c` 如何加载核心、如何把配置/输入/视频/音频解耦。它的 `driver` 结构体是"C 语言写面向对象"的教科书例子。
- **melonds / Flycast**(C++):现代 NDS/DC 模拟器的组织方式,含 HLE 与 BIOS 处理的正确姿势(和 `03-BIOS库` 呼应)。

读大项目的固定方法:**不要试图读完**。找一个具体行为(例如"按键按下后怎么传到游戏里"),从输入回调顺着调用栈读到硬件寄存器写入,一条线读通就赢了。

## 阶段五:自己做游戏(持续)
两条路,选一条:

**A. gbdk-2020(C,资料多)** — 本地:`已clone仓库/工具与ROM管理/gbdk-2020`
- 头文件 `<gb/gb.h>`,核心 API:`wait_vbl_done()`、`joypad()`、`set_sprite_data()`、`show_sprite()`。
- 参照现成完整游戏:`homebrew游戏源码/tobutobugirl`(GB 平台动作游戏,商业完成度)和 `ZGB`(带引擎封装,写起来更快)。

**B. butano(C++,现代工具链)** — https://github.com/GValiente/butano
- 真正的 C++17/20,资源系统(图块/精灵/音乐)靠工具链自动打包,写 GBA 游戏比 gbdk 舒服。
- 参照:`homebrew游戏源码/BridgeQuestGBA`、`beat-beast`(both GBA jam 作品)。

选择建议:**想练 C++ 语法 → butano;想看懂绝大多数 GB 老代码 → gbdk。**

## 阶段六:走到"能在掌机上跑自己的东西"
1. 把自制 ROM 放进掌机的 `ROMS/GB`(或对应目录)→ 前端能识别就说明格式没问题。
2. 想深入就交叉编译:为 arm 掌机(全志 H700/T618 之类)编译 RetroArch core,需要对应的 toolchain。此时你实际上在做固件维护者做的事。
3. 到这一步,你就有能力自己给某个冷门核心打补丁、改默认配置、做主题了——这也是本库 `01-教程库/机型固件` 那些文档的编写者所处的层次。
