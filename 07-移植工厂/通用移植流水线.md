# 通用移植流水线（portkit）

一句话：**给一个游戏，写一份 JSON，跑一条命令，出掌机包。** 同一份 spec 还能出 Windows 验证件和 Switch 目标。

```bash
py -3 工厂.py port route <目录或文件>                # 只读判定输入该走哪条路线，不解压不执行
py -3 工厂.py port new <源码目录> --id mygame        # 按判定直接生成待填草稿；非源码路线拒收
py -3 工厂.py port draft <源码目录> --id mygame     # 扫描出草稿，TODO 都标出来
py -3 工厂.py port plan  specs/mygame.json --target handheld   # 只算不跑，打印将执行的命令
py -3 工厂.py port build specs/mygame.json --target handheld   # prepare→fetch→build→package→verify
py -3 工厂.py port run   specs/mygame.json --target handheld --plan plans/run.json  # 主机运行证据
py -3 工厂.py port status specs/mygame.json --target handheld  # 按记录评成品资格 R0–R6
py -3 工厂.py port list  --dir specs                # 校验全部 spec
```

产物：`F:/_scratch/portkit/<id>/<target>/dist/<名字>.zip` + `report-<target>.md` + `state.json`（断点续跑）。

---

## 1. 先分五类，再谈能不能打包

不同游戏的"能做什么"完全不是一个问题，流水线第一步就是把它放进下面一格：

| 家族 | 典型 | 引擎 | 游戏数据 | 包能不能直接发 |
|---|---|---|---|---|
| `open-engine` | OpenTyrian、OpenTTD | 开源 | 开源/免费 | ✅ 能（rtr:true） |
| `source-port` | EDuke32、Yamagi Quake II、DevilutionX | 开源 | **商业** | ⚠️ 只发引擎，数据玩家自备（rtr:false） |
| `recomp` | 反编译重建工程（Ship of Harkinian 类） | 开源 | **商业** | ⚠️ 同上 |
| `emulation` | 模拟器 + 原版镜像 | 开源 | **原版镜像** | ❌ 只发模拟器前端，镜像玩家自备 |
| `binary-research` | 只有商业 EXE/DLL | 无 | 商业二进制 | ❌ 不出成品，走 `research` 逆向研发 |

`port route <目录或文件>` 会替你做这一步的粗分：只读扫描文件名、构建入口、文件头魔数与包内清单，输出 `B-source / B-recomp / A1-ghidra / A2-rexglue / data-only / existing-artifact / emulation / android-apk / archive / unrouted` 之一，附上证据、阻断和下一命令。它不解压、不执行、不写被扫描目录，判定也不等于家族归类（`family` 仍要你在 spec 里声明）与成品资格。

`port new <源码目录> --id <游戏id>` 把这两步接起来：先跑同一个只读判定，只有 `B-source`/`B-recomp` 才生成 `specs/<id>.draft.json`（`family` 顺手填成 `source-port`/`recomp`），并把判定 JSON 的 SHA256 写进草稿的 `_draft.route.decision_sha256` 供日后对账；判定为其他路线时只报原因，一个文件都不留。

`data.policy` 决定闸门怎么卡：

- `bundled`：必须写 `rights_proof`（哪份许可、哪来的），否则 spec 校验直接不过。
- `free-download`：数据由流水线按 `data.downloads` 里的 URL 下载，**每条都必须钉 sha256**（不钉就不给跑），同样要写 `rights_proof`；解包支持 `lowercase`（引擎按小写名找文件）和 `strip_root`（数据包常套一层 `tyrian21/` 之类目录）。下完落在 `<target>/data`，打包时用 `${data}` 引用。
- `user-supplied`：自动挂一份禁入名单（`*.grp/*.mix/*.mpq/*.wad/*.iso/*.nsp/*.xci…`），**包里出现任何一个就判失败**；同时要求 `data.required` 非空，且启动脚本必须真的检查这些文件（闸门会去 zip 里读启动脚本核对）。
- `none`：不需要数据。

## 2. 结构：一层声明 + 五个可替换零件

```
specs/<id>.json          声明：源码钉在哪个 commit、打什么补丁、给哪个平台、怎么打包、过哪些闸门
  └─ source.repo/commit/local/patches     可复现取源（本地仓库也能当 clone 源，工作副本仍然干净）
  └─ targets.<名>.profile                 host / zig-aarch64 / zig-mingw / mingw64 / devkitpro
  └─ targets.<名>.build.system            cmake / gnumake / autotools / meson / custom
  └─ targets.<名>.build.patches           只给这个目标的补丁（例：mingw 链接方言）
  └─ targets.<名>.package                 启动脚本、port.json、gameinfo.xml、许可证、截图、zip
  └─ targets.<名>.gates                   闸门清单
```

`portfactory/portkit/` 里对应的零件：

| 文件 | 职责 |
|---|---|
| `spec.py` | 校验声明；缺字段、commit 没钉死、数据政策说不清，一律当场报错 |
| `profiles.py` | 工具链垫片：生成 `gcc/g++/clang` 壳、`ar`、`strip`、`sdl2-config`、cmake 工具链文件 |
| `builders.py` | 把 `build.system` 翻成真实命令；统一加固项（`-ffile-prefix-map`、`-Wl,--strip-debug`） |
| `portmaster.py` | 渲染启动脚本 / port.json / gameinfo.xml；确定性 zip（固定时间戳、排序、显式权限） |
| `gates.py` | 闸门实现；未知闸门、闸门异常一律算失败 |
| `runner.py` | 状态机 prepare→fetch→build→package→verify，断点续跑，写 markdown 报告 |
| `draft.py` | 扫源码猜构建系统/依赖/许可证，生成带 TODO 的草稿 |
| `route.py` | 只读扫描任意输入（目录/文件/包），判定 A/B 路线并给出阻断与下一命令 |
| `onboard.py` | 把 `route` 的判定接到 `draft` 上：源码路线出草稿并绑定判定哈希，其余路线拒收 |

## 3. 工具链方言表（踩过的坑已经变成代码）

这些是"同一个引擎，换个宿主机就编不出来"的真正原因，现在全部固化在 `profiles.py` / `builders.py` 里：

| 坑 | 现象 | 固化方式 |
|---|---|---|
| zig 在 Windows 宿主拼链接参数 | `-L F:/x -lSDL2` 被拼成 `-l:F:\x`，ld 找不到库 | `sdl2-config` 只输出 `.so` 全路径 |
| C++ 标准库头 | `zig cc -x c++` 找不到 `<limits>` | C++ 用 `zig c++` 驱动，不用 `-x c++` |
| zig 的 strip 桩 | `zig objcopy --strip-all` 返回 unimplemented | 统一用 `-Wl,--strip-debug`，不依赖 strip |
| GNU ld 与 lld 参数不同 | `-Wl,-subsystem,windows:6.1,--major-os-version,…`、`--enable-auto-import` 被 lld 拒绝 | 目标级补丁改写链接参数，不动全局 |
| RPATH 泄漏 | `-DXXX_LIBRARY=绝对路径` 把构建机路径写进二进制 | cmake 强制 `-DCMAKE_SKIP_RPATH=ON`，闸门复查 |
| `__FILE__` 泄漏 | 二进制里能看到 `F:/_scratch/...` | `-ffile-prefix-map=<src>=.`，闸门复查 |
| zig 自带 mingw libc 缺符号 | `strndup/mempcpy/pthread_spin_*/wmem_*/long double math` 全缺 | Windows 验证优先真 mingw64（winlibs），zig-mingw 只兜底 |
| ALSA 硬耦合 | 关掉 ALSA 后 `ALSADrv_*`、`ALSA_ClientID` 仍被引用 | 用补丁把表项和数据成员一起包 `#if`，不放宽编译选项 |
| make 的空值等于没定义 | 命令行传 `SUBPLATFORM=` 想禁用某后端，`ifndef` 仍成立，后端又被打开 | 不传空值，传一个明确的非目标值（如 `HANDHELD`） |
| pkg-config 不能"什么都承认" | 垫片对任何包都返回成功，工程就去编 ALSA/PNG 这些宿主机后端，直接找不到头文件 | 垫片只承认 sdl2，其它包一律报不存在 |
| 只取 `--libs-only-l` 的工程 | OpenTyrian 的 Makefile 把 `--libs` 拆成 `-L`/`-l` 两段，垫片对这两段都回空，链接时 SDL2 直接缺席 | 垫片对 `--libs-only-l` 也吐 `.so` 全路径（gcc/clang 都接受全路径输入） |
| mingw make 撑不住带引号的 recipe | `-DFOO='"bar"'` 实测被拼成一个畸形参数，**后面整行都被吞进去**，报 `zig: error: no input files` | `build.make_vars` 里出现双引号就在计划阶段报错，要带引号的宏改用 `custom` 构建（命令直接交给 bash，不经过 make） |
| 数据包多一层目录 | `tyrian21.zip` 解出来是 `data/tyrian21/*`，引擎按 `data/*` 找，启动时判定"数据不完整"直接退出 | `data.downloads[].strip_root` |
| Windows 控制台 GBK | CLI 的中文报告全是乱码（`# Tyrian �� handheld`） | `cli.main()` 启动时把 stdout/stderr 重设为 UTF-8 |
| zip 排序要按归档名 | Windows 路径比较不分大小写，按宿主路径排序打出来的包自检会判"未排序" | 用归档内相对路径字符串排序 |
| msys2 程序从 Git Bash 启动时环境是空的 | devkitPro 的 `make.exe` 被 Git Bash 拉起后，连 `FOO=hello` 都看不到，`Makefile` 立刻报 "Please set DEVKITPRO"；同一个 make 从 devkitPro 自己的 bash 拉起就正常 | `Profile.shell`：该档案的所有命令都改由 `F:/devkitPro/msys2/usr/bin/bash.exe -lc` 执行，且 PATH/DEVKITPRO/PORTLIBS 全给 POSIX 路径 |
| devkitPro 的 Makefile 递归 | 模板里 `$(MAKE) -C build -f $(CURDIR)/Makefile`，`CURDIR` 在递归时已变成 build 目录，结果又去跑上游那个 SDL 版 Makefile，报 `visualc/resources.rc` 找不到 | 递归改指 `$(TOPDIR)/Makefile.switch`（本文件自己的路径） |
| msys2 会把 `-D` 里的 POSIX 路径当成本机路径改写 | `-DTYRIAN_DIR='"/romfs/data"'` 编进去变成 `F:/devkitPro/msys2/romfs/data`，NRO 里多了构建机路径，Switch 上 RomFS 也挂错 | `build.env` 里设 `MSYS2_ARG_CONV_EXCL=-DTYRIAN_DIR`，只豁免这一个参数，其它 `-I/opt/...` 仍照常转换 |
| NRO 上的路径闸门要按目标定针 | 精灵数据里恰好有 `/f/` 三个字节，用默认针（含 `/f/`）会把正常数据判成路径泄漏 | `target.build_path_needles` 覆写针表；Switch 目标用 `["_scratch","F:/"]` |

## 4. 闸门：只有全绿才算做完

| 闸门 | 查什么 |
|---|---|
| `elf` | 架构（aarch64=183）、`DT_NEEDED` 白名单、禁止 libstdc++、RPATH 必须为空、glibc 上限 |
| `no_build_paths` | 二进制里不许出现 `_scratch` / `F:/` / `/f/` |
| `portmaster_layout` | 根目录 .sh 有可执行位、含 `get_controls`+`pm_finish`、port.json 顶层 5 键与 attr 12 键齐全、items 指向真实条目、有 gameinfo.xml |
| `data_policy` | 包里不许有用户自备数据；`required` 必须在启动脚本里被检查 |
| `licenses` | 声明的许可证文件真的在包里 |
| `deterministic_zip` | 时间戳统一、条目有序、无重名 |
| `screenshot` | PNG 魔数 + 至少 320×240 |
| `nro` | Switch NRO0 魔数 + 首指令是 ARM64 分支 |

"没跑"不等于"通过了"：闸门返回 `pass/fail/blocked` 三态，任何 `blocked`（缺工具、缺文件）都会让流水线停下并写明原因，不会假装成功。

## 5. 接一个新游戏要做什么

1. `port route <目录或文件>`：先只读判定路线。判定为 `data-only`/`emulation`/`archive` 时，说明现在这条流水线还接不了，别硬填 spec。
2. `port new <源码目录> --id <游戏id>`：判定是 `B-source`/`B-recomp` 就一步生成 `specs/<id>.draft.json`（同时留一份 `<id>.route.json` 判定记录，哈希写进草稿），把猜到的构建系统、依赖、许可证、TODO 都列出来。已单独跑过 `port route`、或想自己挑 `family`，仍然可以直接用 `port draft`。
3. 人工填四件事：**源码 commit**（必须钉死）、**构建参数**（这个项目自己的开关，比如 `USE_OPENGL=0`）、**数据政策**（能不能带、必须带什么）、**打包信息**（端口目录名、启动脚本名、许可证文件、截图）。
4. `port plan`：只看命令，不执行。构建参数错了在这里就能看出来。
5. `port build`：五阶段跑完；失败会停在具体阶段，日志在 `<work>/<target>/logs/`，也可以用 `port repair-request` 把失败变成可交给模型的证据包。
6. `port run`（可选）：在受控目录里真跑产物、按检查点取证据；`port status` 把已有记录换算成 R0–R6。
7. 改完再跑：默认跳过已通过阶段；`--force` 全量重来。

改一处 spec 就能换平台：`profile` 从 `zig-aarch64` 换成 `mingw64`，产物就变成 Windows 验证件（用于在本机跑起来截图、验证玩法）；换成 `devkitpro` + `package.platform: nro-zip`，产物就是 Switch 的 `.nro` 加许可证的 zip（数据走 romfs，图标来自 spec 里的 `icon.jpg`）。

## 6. 现在能到什么程度、到不了什么程度

**已经做到的**（都是本机实跑，数字取自各自的 `state.json`）：

| spec | 目标 | 结果 |
|---|---|---|
| `specs/duke3d.json` | handheld（zig-aarch64 / PortMaster） | 5 阶段 + 7 闸门全绿，`Duke3D.zip` 1,631,625 B，sha256 `7f0699ac…` |
| `specs/duke3d.json` | windows（mingw64，验证用） | 5 阶段 + 5 闸门全绿，`Duke3D-win-proof.zip` 2,573,198 B，sha256 `c545fb61…` |
| `specs/tyrian.json` | handheld（zig-aarch64 / PortMaster，含免费数据下载） | 5 阶段 + 7 闸门全绿，`Tyrian.zip` 5,046,805 B，sha256 `782ca9c0…`，包内 112 条目（引擎 + 106 个免费数据） |
| `specs/tyrian.json` | switch（devkitpro / libnx，`nro-zip`） | 5 阶段 + 4 闸门全绿，`Tyrian-switch.zip` 7,753,487 B，sha256 `3c4605f8…`；内含 `opentyrian.nro` 18,820,906 B（sha256 `6cef85cf…`，0x10 处是 NRO0，前面是 homebrew 签名头）、`licenses/COPYING`、`README.txt`；编译 12.3 s（romfs 已带 106 个免费数据文件）；`--force` 全量重跑两次 zip 字节一致 |
| `F:/_scratch/portfactory_onboard_20261101/specs/opentyrian-snapshot.json`（`port new` 生成的草稿填完） | handheld（zig-aarch64 / PortMaster） | 5 阶段 + 7 闸门全绿，`opentyrian-snapshot.zip` 5,049,758 B，sha256 `c321e132…`，112 条目；`port status` 评到 R3，R4/R5/R6 blocked |

tyrian 的第二次打包与第一次字节一致（`deterministic_zip` 闸门 + 实测复跑）；`tests/test_portkit.py` 23 项全过。

Quake、Quake II、Quake III、Wolf3D、Diablo、CnC、OpenTTD 的手工流程可以照同样的形状改写成 spec（每个都要现填构建开关和打包信息）。

**还没有的**：

- Switch 目标能出 `.nro`（本机 devkitPro 16.1.0 / devkitA64），但**没有真机验收**：闸门只证明"这是个结构正确的 NRO"，不证明"插进 Switch 能玩"。按 README 里既有的口径，这类产物在真机回放记录补上之前不能标"成品"。
- `emulation` 只负责把模拟器前端打包，镜像永远由玩家提供；`recomp` 需要先把反编译工程构建出来，数据同样自备。
- `binary-research` 不出成品包，走 `research` 那条函数级逆向线。
- 本机没装 cmake/ninja：`cmake` 类项目会在 prepare 阶段明确报"缺少工具"，不会往前硬跑。
- R4 主机运行只在 spec 有可在本机跑的产物时才拿得到：像 `opentyrian-snapshot` 只声明了 aarch64 目标，而本机没有 Windows 侧的 SDL2 开发库，`port run` 就没有可跑的东西——它停在 R3，`port status` 会照实写 blocked。
