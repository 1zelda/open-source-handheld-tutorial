# 复古游戏文献来源库（FC / 街机 / SFC / MD / GBA / PS1 等通用）

> **本文不是主数据。** 主数据是 [`来源库/sources.json`](来源库/sources.json)（机器可读，79+ 条），
> 下面 `GENERATED` 块里的站点清单/选站表/禁用清单全部由 `python -m taspipe.sources render --write` 单向生成。
> **手改生成块无效**，`python -m taspipe.sources audit` 会判 `render_sync` 红。要改站点、状态、取证，改 JSON 或用 `ingest`/`log`/`recheck` 命令。
>
> 用途：给"逐游戏知识包 author"当搜索起点。**规则：先定 ROM 身份 → 先查库（route）→ 库内来源覆盖不全才走延伸段 → 判"查不到/不存在"之前必须扫 B站+网盘中文层并留 miss 记录**（11-16 立的规矩：搜不到别说成不存在）。
> 首发：2026-11-18（《热血足球联盟》验证轮沉淀）；同日全聚集地复盘轮扩充街机 hack 层/版本鉴定层/纸媒层/宏层；同日**系统化改造**：来源变成主数据 + 可执行路由 + 检索台账 + 入库去重 + 审计闸门。
> **维护规矩：命中即 `log` 落取证产物，新站即 `ingest` 入库分类，死站要 `recheck --mark-dead --reason` 给当期证据。每个游戏结项时跑一次 `audit`。**
> **状态口径**（与 JSON 一致，不再有第二套标记）：`verified_read`=本机取到正文并核对（必须带取证文件）；`snippet_only`=只拿到搜索快照；`unreachable`=本机直连失败但站活着（走快照）；`candidate`=知道存在、本轮未验；`dead`=已关停（必须带当期证据）。

## 0. 搜索顺序（固定流程，已落成代码）

在 `F:\开源掌机教程\_工具脚本` 下运行。**S1 调研必须先跑 route，禁止直接自由搜。**

```bash
# ① 定身份 + 出检索计划（身份不明 => blocked，不出计划）
py -3 -m taspipe.sources route --game "拳皇98" --set kof98eck --platform ARCADE \
    --want 出招表,必杀宏,金手指,彩蛋 --out F:/taspipe_scratch/route_kof98eck.json
#    主机游戏用 --rom <本地路径> 代替 --set（按 sha1 + 扩展名定平台）

# ② 按计划 primary 段逐站查（verified_read 优先，unreachable 只走快照）
#    primary 未查完不得自由扩大搜索；forbidden 段（dead）禁止直连

# ③ 命中/快照/未命中都要落台账（hit 必须带真实存在且非空的正文取证文件）
py -3 -m taspipe.sources log --source-id hackrom_cn --game kof98eck --want 金手指 \
    --verdict snippet --evidence "_工具脚本/taspipe/游戏包/来源库/取证/xxx.md"
py -3 -m taspipe.sources log --source-id tieba_baidu --game kof98eck --want 彩蛋 --verdict miss

# ④ primary 全 miss 才走 extension（candidate 候选层）；发现新站立即入库
py -3 -m taspipe.sources ingest --url https://新站/页 --name "站名" --layer cn_community \
    --platforms ANY --want 攻略,彩蛋

# ⑤ 下"查不到/不存在"结论前，中文网盘层 + B站 必须已有 miss 记录
py -3 -m taspipe.sources claim-absence --game kof98eck --want 彩蛋

# ⑥ 结项：重生成人读清单 + 审计
py -3 -m taspipe.sources render --write
py -3 -m taspipe.sources audit
```

为什么是这个顺序：同一个"拳皇98"有几十种改版，版本不同必杀指令与角色阵容就不同；本地模拟器自己的 setlist 是最快最权威的口（`local_fbneo_setlist`），先读出全名再决定用哪份表。route 会把这件事做成硬门：身份未定直接 `blocked`。

- **中文纸媒是隐藏王牌，但本轮只到搜索层**：archive.org 的电软合订本带 `_djvu.txt` 全文（`archive_dianruan`），比百度文库零散转载可靠；**本轮只确认文件存在，未取正文**（旧版本文标 `[已读]` 属过度声称，已更正为 `snippet_only`）。真读后落取证文件再 `log --verdict hit` 升级，OCR 脏字要回图核对。
- **知识包来源必须是结构化引用**：`{source_id,url,status,verified_date,element_ids,note}`。自由文本 URL、库里没有的野 source_id、引用 dead 站，`audit` 一律判红。
- **要素必须有来源支撑**：`audit` 逐要素反查（79 个要素全覆盖）；只有快照/不可达/候选层支撑的要素判 `inconclusive`（**不是通过**），要升 verified 须真读正文落取证或本机实测落记录。
- **取证文件必须真实存在且非空**：`verified_read` 缺取证 = schema 直接拒；`log --verdict hit` 不带正文产物 = 判 inconclusive，不算命中。
- **「不存在」声称要有台账支撑**：`claim-absence` 要求中文网盘层 + B站 都已留 miss 记录，否则 blocked 并点名缺哪层。
