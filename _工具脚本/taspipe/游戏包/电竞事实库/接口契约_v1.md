# 电竞事实服务接口契约 v1（2026-11-20 冻结）

> 阶段一第1天冻结件。权威规格 = 根目录 `全域游戏知识库与电竞落地_实施计划_2026-11-20.md` §2.2–§2.5。
> 改动须走集成负责人串行合并并升版本号；不许就地偷改口径。
> 配套冻结件：`schema_v1.sql`（表结构）、`source_policy_v1.json`（E01–E19 权限）。

## 1. 架构分工

- SQLite 结构化主库：事实值、关系、时间条件。
- 不可变原始快照：`source_snapshot` + 原始文件（content_sha256 绑定）。
- 现有 BM25/BGE 文本索引：规则解释、采访、机制说明、证据定位；**电竞语料独立分区，
  不进冻结 625 块 base 索引的全局统计量**。
- 同一事实单一权威数据位；检索用自然语言卡片从结构化记录**确定性生成**，不维护第二份手写答案。

## 2. 查询输入契约

```text
game_id / entity_id          必填其一；多义时要求澄清，不猜
predicate                    问题类型（赛果/阵容/转会/补丁数值/规则…）
competition / season / stage / region   赛事身份（电竞事实必填到可定位赛事）
as_of / patch_id             现实适用时间点或补丁钉
knowledge_as_of              可选：回放本库当时知道什么（用 recorded_at/superseded_at）
```

## 3. 执行顺序（不许颠倒）

1. 明确游戏、实体和问题类型；多义 → 需澄清。
2. **先硬过滤**：身份、时间、版本、授权范围（source_policy）。
3. 再召回和重排（文本域走现有检索栈）。
4. 核验主体、属性、数值归属、否定、限定范围、证据资格。
5. 检查冲突、撤稿（retraction_status）、更新缺口。
6. 确定性模板输出答案，固定显示适用条件（"截至X赛季/X补丁"）。

## 4. 查询输出契约（与现有 kb.query 共存，保留原状态词）

```text
status: pass / miss / inconclusive
reason_code
claim: {主体, 属性, 值, 适用条件}
answer_text: 确定性模板输出
selected_evidence: 恰好1块（pass 时）
retrieval_hits: 相关材料，不等于证据
dataset_revision、query_conditions
```

- 一个原子事实，一个选定证据块。
- JSON 事实的证据块 = 快照中该对象的字段值＋身份上下文（JSON Pointer 定位），不强迫变自然段。
- 整份阵容被同一官方名单块完整证明 → 可作集合事实。
- 多来源传记拆多张事实卡，每张各一个证据块。
- 跨记录派生值（如生涯总冠军数）无单块完整证据 → 严格模式不作原子 pass，展示分项事实；
  接受"可复算派生证据"须单独扩契约。

## 5. 双时间语义

| 字段族 | 含义 |
|---|---|
| valid_from / valid_to + start_bound_kind / end_bound_kind | 现实中何时适用 |
| recorded_at / superseded_at | 本库何时知道这一版本（纠错回放） |
| announced_at vs effective_at（transfer_event） | 官宣≠生效；不提前切换归属 |
| time_precision | second/day/month/unknown；未知不填午夜伪装 |
| last_verified_at / verification_basis | 刷新失败**不许**更新 last_verified_at |

三类事实分别处理：

- 历史事件（赛果/官宣）：不因旧失效；查赛事身份、最终状态、修订/撤回。
- 状态（当前阵容/现役/当前版本）：要有效区间＋完整更新覆盖＋近期核验；
  旧页面可访问≠现状；覆盖不全 → "无法确认当前X；已有资料仅能证明截至某日"。
- 规则/机制：按 rule_version / patch_deployment 匹配，不拿发稿日期替代生效版本。

"现在" = 本次查询时间＋展示时区，不是抓取时间。
比分分单位：series_games / map_rounds / in_game_kills（score_unit 显式）。
重赛（attempt_number）、弃权、行政判胜（result_method）、取消显式记录；不仅凭比分推断赢家。

## 6. 权限契约

- source_policy 五维（automated_access/local_retention/commercial_use/quotation/redistribution）
  各取 allowed/denied/unknown；unknown 不得当 allowed 用。
- 采集前置闸门：该来源该用途五维中任一 denied → 拦；unknown → 待核队列，不进生产。
- 凭证值永不落本库/本表；authorization_ref 只存引用名。

## 7. 入库流水线（阶段2起实现，此处先冻结顺序）

`发现 → 权限准入 → 原始快照 → 解析 → 实体匹配 → 候选事实 → 核验 → 发布`

固定拦截：登录页/错误页当正文；分页未取完标全量；null比分变0；转载算独立来源；
撤稿后旧事实仍在生产答案；抓取失败刷新核验时间；重复导入增殖事实。
