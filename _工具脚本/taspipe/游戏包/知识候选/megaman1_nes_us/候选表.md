# 洛克人 1（NES/USA）八要素知识候选表

> 任务 C 交付件之一。目标版本：**Mega Man (NES, USA, 1987 Capcom)**，干净 [!]/No-Intro 对应 dump。
> 本表是**文献候选**，不是实测结论。所有宏帧号、RAM 地址、检测 RGB/阈值/帧号一律标 `未实证`；
> 凡文献能确定的机制标来源编号（F/S/L 见 `来源清单.md`）。每要素 13 字段齐全。
>
> 字段：ID / 名称 / 所属角色·资格 / 版本 / 前置场景 / 触发方法 / 可观测前置 / 成功特征 /
> 易混淆普通动作 / 困难反例 / 原文·页码·链接 / 证据等级 / 尚需探针。
>
> 通用输入口径（S1 Whammychip 摘要 + F2 L97 全文互证）：**B = 释放当前武器；START = 武器选择菜单（暂停动作）；SELECT = 普通暂停**。
> 通用能量口径（F1 全文）：满武器能量条 = 28 单位。
> 通用前置风险（L3/L4）：`current_weapon` 与 `owned_flags` 地址**未知**；showcase 用 addr 95(0x5F) 值 1–7 猜选武器、addr 107–113(0x6B–0x71) 值 28 猜能量，**全部未实证**；若游戏校验 owned_flags，只写能量+猜选武器可能根本放不出武器。

## 附：八要素共性检测风险（authoring 时必须处理）

1. **角色变色陷阱**：C/I/B/F/E/G 六件武器都会改角色配色（F1 各 Color Scheme）。检测 region 若覆盖角色且只认颜色分数，会把"装备了武器"当成"释放了武器"。中立反例共享 patches（角色已变色）正是为了暴露这个——**检测器必须锁定弹丸/光束/爆炸/举块动作本身，排除角色像素**。
2. **HUD 碰撞**：能量条/武器图标在屏幕顶部，thunder_beam 的近全屏 region（y 起 0.12）尤其危险。region 应避开 HUD 带。
3. **Magnet Beam 配色不变**：唯一不能靠角色变色判前置的武器；且光束从**身后**起始，region 左界要够左。
4. **Super Arm 有 block ≠ 释放**：反例必须保留 block 在原位，正例必须出现举/投/碎动作。
5. **Hyper Bomb 飞行 ≠ 爆炸**：detection.frame 必须落在爆炸窗，不是投掷窗。
6. **Fire Storm 单 check 不够**：任务书要求火球+护盾两者，showcase 当前只有一个 shield_sig。
7. **所有 RGB/阈值/帧号都是猜的**：L4 的 frame_region_color_fraction 参数全部 authoring_unverified，必须用真实正/负帧数据重定（任务书 L1 §4 第 4 步）。
