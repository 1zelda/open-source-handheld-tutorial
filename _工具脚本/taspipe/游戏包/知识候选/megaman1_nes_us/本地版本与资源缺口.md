### 2.1 异常组合（catalog `blockers` 逐字，L3）

> `local mega_man_usa.nes / megamanhd.nes cannot reach gameplay: stage-select D-pad inert (held 40 frames), Start jumps straight to a 'CUTMAN / CLEAR POINTS / 80000' cutscene and returns to select; weapon-energy region pre-full at boot. Suspected modified/trained or bad dump (see 测试问题与闸门说明书.md §23).`

拆解三个异常信号：

1. **选关方向键无效**（按住 40 帧仍不动）——正常 MM1 选关菜单方向键应能移动光标。
2. **未战斗直接进 CLEAR POINTS 过场并退回选关**（Start 直接跳 `CUTMAN / CLEAR POINTS / 80000`）——正常流程是进关卡打 Boss 后才计分。
3. **开机武器能量区预满**——正常新开档 Boss 武器未获得、能量不应预满。

判定：**疑似修改版/训练版或坏 dump**（catalog 原文 `Suspected modified/trained or bad dump`）。
⚠️ 计分画面本身**不是**异常（MM1 正常有计分，见 §1）；异常在于"未战斗就进计分过场"这个**行为组合**。
这两个 ROM **不得**用于武器 authoring，其过场帧**不得**冒充武器展示（任务书 L1 §2）。

### 2.2 干净开局签名（4 条件，任务书 L1 §4 第 1 步逐字）

新 ROM 必须**同时满足**：

1. 标题与选关菜单方向键可正常移动；
2. 能进入可控制角色的真实关卡 gameplay；
3. 不会在未战斗时反复进入 CLEAR POINTS 并退回选关；
4. 武器菜单与 HUD 可正常观察和操作。

任一不满足 → 仍是坏候选，继续 `blocked_resource`，不进入 authoring。

## 4. RAM 地址缺口（文献只有候选，必须 gameplay 差分）

来源 L3 `ram_documented_unverified`（DataCrystal/nesmaps 搜索快照，来源清单 S16/S17）：

| 字段 | 候选值 | 状态 |
|---|---|---|
| life | 0x006A | 未实证 |
| invincible | 0x0055 (=04) | 未实证 |
| all_stages_complete | 0x005D (=FF) | 未实证 |
| weapon_energy_range | 0x006B..0x0071 | 未实证（与武器 ID 映射未确认） |
| **current_weapon** | **null** | **未知，必须差分发现**（L4 用 addr95=0x5F 猜，未证） |
| **owned_flags** | **null** | **未知，必须差分发现** |

L3 note 逐字：`addresses from DataCrystal/nesmaps search snippets only; NOT confirmed in-game. current-weapon and owned-flags addresses unknown; must be discovered by in-game ramdump diff once a clean ROM reaches gameplay, then each verified with detector pos/neg.`

⚠️ **owned_flags 未知是硬风险**：L4 的 patches 只写能量(107–113=28)+猜选武器(95=1..7)，**没有写 owned_flags**。
若游戏逻辑校验"是否持有该武器"，则即使能量满、选武器地址猜对，按 B 也可能**放不出武器**。
必须在真实 gameplay 内：获得武器前后差分 → 定位 owned_flags → 写入后用输入宏真实释放并观察游戏逻辑认可（任务书 L1 §4 第 3 步）。
