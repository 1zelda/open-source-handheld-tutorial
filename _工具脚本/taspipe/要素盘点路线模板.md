# 要素盘点可复用生产路线模板（正确路线 + 错误阀门）

> 立规出处：用户 2026-11-10「在测试的过程中把正确的路线逐渐写出来、错误的阀门也写出来，
> 之后这个路线就可以用来制作其他游戏的」。本文件就是那条**可复用路线**的 durable 记录。
> 形态边界（沿用 `目标与实施路线.md` §0）：**通用生产流程 + 逐游戏知识包**，不是「任意 ROM 丢进去自动识别」。
> 三份文档分工：`目标与实施路线.md` = 项目 T 阶段/现状台账；`测试问题与闸门说明书.md` = 踩坑根因+闸门目录；
> **本文件 = 逐游戏生产时的操作路线（步骤顺序 + 每步产物/判据 + 每步拒绝阀门）+ 逐游戏填槽清单**。
> 通用部分（§1 步骤、§2 阀门）跨游戏不变；逐游戏部分（§3 槽位）每款填一份，填进 `游戏包/*.pack.json` + §4 式逐游戏卡。

---

## 1. 正确路线（有序步骤；每步 = 动作 / 产物 / 判据 / 模块）

> 只搜「几个动作宏」的参数（距离/时序/资源），**不从每帧所有按键组合盲搜**（`b^h` 爆炸）。
> 每步判据不满足就停在该步、报 blocked/inconclusive，**不带着假状态往下走**。

- **S0 立项与资源确认**
  动作：选**名作**（用户政策：不随便拿游戏测）；确认 ROM/电影/金手指走合法自有路径。
  产物：registry 条目 + `assess` 判定。判据：`registry.assess` = replayable（movie 路径）或资源齐备（statejump 路径）。
  模块：`registry.py`、`acquire.py`。
- **S1 出招表 / 要素清单调研**
  动作：网上查出招表/要素清单（必杀、道具、变身、彩蛋），**不臆造按键与 RAM 地址**；杂志只作文案+选题库。
  产物：要素清单（element_id / kind / 触发按键 / 预期可视结果）。判据：每个要素有可观察的触发输入与可视结果。
  模块：人工调研（WebSearch），落进 pack 的 `note`/`sources`。
- **S2 能力与证据门控**
  动作：跑 `backends.probe`；savestate/ram_read/interactive_step 转真须**双闸**（BizHawk 可用 + `验证/t3_statejump/report.json` 全 pass）。
  产物：capabilities 表。判据：无证据/缺 exe => 诚实 `supported=False`/`blocked`，不硬跑。
  模块：`backends.statejump_evidence`、`backends.BizHawkNESBackend.probe`、`statebuild.build_state`。
- **S3 状态构造机制选型**
  动作：有现成 TAS movie => movie 路径（`auto.run_movie_elements`）；无 movie 但需走位/改 RAM => **statejump 路径**；街机招式 => `search.py` 短窗口搜索。
  产物：机制决定 + JobSpec.source。判据：source 与机制匹配；statejump 源须 S2 双闸已过。
  模块：`auto.orchestrate`、`statebuild`、`search.py`。
  **已知缺口**：`auto` 目前只有 movie/arcade 采集分支，**statejump 采集分支（run_statejump_elements）尚未接线**；
  在此之前 statejump 源要素用 `StateSession` 探针脚本手工驱动（§4 例），不声称 auto 端到端。
- **S4 导航摸底到「要素前一刻」**
  动作：起 `StateSession`，逐段输入+截图，摸出 boot→…→要素前一刻 的输入链；**实测输入锁定期**（开头若干帧忽略输入）；
  菜单/标题屏单帧按键可能落在动画子态被忽略 => 改**按住多帧**逐轮试。
  产物：导航输入链 + 逐段截图。判据：截图确认到达「要素前一刻」画面（如 KICK OFF / 持球站立）。
  模块：`statejump.StateSession`(start/run/macro/shot/ping)。
- **S5 save 可复现 base 快照**
  动作：在要素前一刻 `save(name)`；快照与截图落 **ASCII 临时工作目录**（中文路径进 Lua io 会坏）；长期保存 shutil 拷出。
  产物：base.state + base 截图。判据：跨进程 reload 同一 base 字节一致（确定性）；后续所有 attempt/确定性比对**共享同一 base**。
  模块：`statejump.StateSession.save/load`、`verify()`。
- **S6 触发输入搜索**
  动作：从 base 用 `attempt(state, spec, extra, shot)`（load+宏+空档+截图，单指令原子）秒级试宏；
  只调几个动作宏的参数；球类/控球类先解决**球权/持球**（ contested possession 是逐游戏搜索步，不是给定）。
  产物：命中触发的宏谱 + 帧窗 + 触发截图。判据：宏真生效（`macro_is_effective` = 画面**不**相等）且出现要素可视结果。
  模块：`statejump.StateSession.attempt/macro`、`statejump.macro_is_effective`。
- **S7 检测器 authoring（场景级视觉）**
  动作：选受控插件（`frame_region_color_fraction` 等）+ region/rgb/tol/min_fraction；抽**正例帧**与**多个负例帧**；
  **不臆造 RAM 地址**（除非实证发现）；判别量要在正/负两侧都有余量。
  产物：pack 的 `success_checks` + `frames` + `negative_cases`。判据：正例分数过阈、负例分数低于阈（两侧余量充足）。
  模块：`detect.py` 受控插件、`游戏包/_template.pack.json`。
- **S8 正负例双闸验收**
  动作：`python -m taspipe.gamepack run <pack.json>`；正例帧必过 success_checks，**每个负例帧必被同一 checks 拒**。
  产物：验收报告。判据：正过 + 全负拒 = 检测器合格；证据不足 => **inconclusive**，不静默通过。
  模块：`gamepack.run_element`。
- **S9 切剪 + 导出**
  动作：按 frame_range 切剪（`clipper.run_cut`）→ 合成（`exporter.compose`，含边框/原声）。
  产物：要素片段 mp4。判据：帧数保留、音画时长一致、抽帧确认要素画面在切剪窗内。
  模块：`clipper.py`、`exporter.py`、`record.mux_av`（`-af apad` 防截帧）。
- **S10 立规收尾**
  动作：本轮每个新坑**二选一**落地——selftest 断言/生产路径检查（看绿灯计数涨），或写进 `测试问题与闸门说明书.md`（根因+规避）。
  产物：新闸门或新说明书条目 + 基线更新。判据：不允许「这次修好就过去」。
  模块：`selftest.py`、说明书。

## 2. 错误阀门（每步拒绝条件；命中即停 / inconclusive，不静默通过）

- **G0（S0）**：非名作 / ROM 来源不合法 / assess 非 replayable 且资源不齐 => blocked，不开工。
- **G1（S1）**：要素无可观察触发输入或可视结果 / 按键靠猜 => 该要素 inconclusive，不写进 pack 冒充。
- **G2（S2）**：缺 BizHawk 或 `t3_statejump/report.json` 缺失/损坏/未全 pass => 能力 False、statebuild blocked（反证格：可用但无证据仍 False）。
- **G3（S3）**：source 与机制不匹配；statejump 源但 S2 未过 => blocked；**statejump 源声称 auto 端到端（分支未接线）=> 不实**。
- **G4（S4）**：把「输入锁定期无反应」误判为注入失败（说明书 §19.10）；单帧按键落动画子态被忽略却以为到达 => 以截图为准，未达要素前一刻不进 S5。
- **G5（S5）**：快照/截图路径含中文或空白 => `format_command` 拒（§19.6）；确定性比对用了不同 base => 误报 desync（§19.11），须共享同一 base。
- **G6（S6）**：`macro_is_effective` 把「画面相等」当有效 => 假阳性绿灯（§19.7，最危险假阴性反转）；球权未解决就试必杀 => 触发不了，报 inconclusive 不造假。
- **G7（S7）**：插件未注册 / 参数缺失 => detect 返回 **inconclusive**（绝不静默 pass）；判别量正负无余量 / 臆造 RAM => 检测器不合格。
- **G8（S8）**：正例不过 或 任一负例未被拒 => 检测器不合格；证据不足 => inconclusive。
- **G9（S9）**：`-shortest` 截帧（音轨稍短丢结尾帧）=> 用 `-af apad`；帧数/音画时长不符 => fail；切剪中点不在要素窗内 => 重选 frame_range。
- **G10（S10）**：新坑只修不落地 => 违反立规；看门狗按程序名裸子串点框误伤主窗口（§20）=> 点框只认具体模态框标题 + 主窗口签名显式跳过。
- **通用协议阀（statejump 全步骤）**：CRLF 毒指令（§19.1）、模板字面 CR（§19.2）、截图竞态拷旧图/半截图（§19.3）、`frameadvance` 在 pcall 内 yield 崩（§19.4）、resp 用 rename 不可见（§19.5）、校验抛裸 ValueError 致 selftest 静默退出（§19.9，须 SchemaError）。

## 3. 逐游戏填槽清单（每款填一份 → `游戏包/<game>_<element>.pack.json` + 逐游戏卡）

| 槽位 | 内容 | 来源步骤 |
|---|---|---|
| game_id / game_revision_id / platform / backend_id | 游戏与版本、平台、后端 | S0 |
| 导航输入链 | boot→…→要素前一刻 的逐段输入（含按住帧数） | S4 |
| 输入锁定期帧窗 | 开头忽略输入的帧数（实测，因游戏而异） | S4 |
| base 快照 | 要素前一刻 save 的 .state 路径（ASCII 工作目录拷出） | S5 |
| 触发宏谱 + frame_range | 命中触发的宏 + 切剪窗（中点落在稳定要素窗内） | S6 |
| 检测器 | plugin_id + params(region/rgb/tol/min_fraction) | S7 |
| 正例帧 / 负例帧 | ≥1 正 + 多负（站立/低腾空/落地后等易混态） | S7 |
| sources | 实跑回放/截图证据引用（run_xxx.mp4#frameN） | S7/S8 |
| note | 出招表出处、判别量口径、已知缺口（诚实） | S1/S7 |

## 4. 逐游戏卡示例：热血足球2代（热血足球联盟 / Kunio-kun no Nekketsu Soccer League, FC 1993）

**已验证（产物级）**
- 机制：无本地 TAS movie => statejump 路径；`验证/t3_statejump/report.json` 9/9 全 pass（RAM 回环/宏有效/确定性 reload·macro·跨进程）。
- 导航输入链（实测，`验证/t3_soccer2_moves/probe2~4`）：boot `run(1200)`（信件自动到标题）→ **按住 Start×10帧** 逐轮：×2 到模式选择、×3 队选择、×4 对阵 VS、×5 休息室（光标默认「开球」）、×6 进场地 **KICK OFF（冻结等输入）**。
- 输入坑：标题屏**单帧** Start/A 落在动画子态被忽略 => 须按住多帧（probe1 单帧失败、probe2 按住成功）。
- base：`probe4/matchbase.state`（KICK OFF 冻结，我方中锋持球）。
- 看门狗误伤修复：`_should_dismiss`/`_is_emuhawk_main_window` + selftest +26（基线 331/331）+ 说明书 §20；`loop_startup.py` 5/5 稳定。
- 出招表（S1，网上查）：必杀射门 = 持球跳起(A+B) **最高点按 B**；最高点前 B = 顶球、后 B = 倒挂金钩；按键金手指 = 比赛中 Start 后 `AAABAAABAAAAAAA` 解锁全部必杀。

**诚实缺口（不造假，待 S6/S7）**
- KICK OFF **冻结态忽略跳跃输入**（A+B 不启动/不起跳，probe6 实证）；须先用被接受的开球输入启动比赛。
- 盲传（B）会** relinquish 球权**给对手（probe5 实证）；contested possession 是逐游戏搜索步。
- 必杀触发宏谱 + 帧窗 + 检测器正负例**尚未 authoring**；当前报 inconclusive，不冒充已复现。
- 候选稳健路线：点球比赛模式（保证持球）或从 base 搜「开球→接球→持球跳→最高点B」时序；二者都须过 S8 双闸才算要素成立。

## 5. 迁移到其他游戏（举一反三）

- 换游戏**只填 §3 槽位**，不改 §1 步骤顺序与 §2 阀门；通用闸门（协议/证据/正负例/看门狗）已在全库 selftest 钉死。
- 每款游戏的「输入锁定期、导航链、球权/持球构造、检测器 region/阈值」是**逐游戏知识**，实测后填槽，不跨游戏硬套。
- 本轮新坑一律按 S10 二选一落地；竞态型 Heisenbug 抽纯函数 + 双向反证夹具转成确定性闸门（§20 范式）。
