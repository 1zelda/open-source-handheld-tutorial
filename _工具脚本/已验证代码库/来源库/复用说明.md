## 1. 这套东西解决什么

以前 `复古游戏文献来源库.md` 是没人消费的手写清单、知识包 `sources` 是自由文本 URL ⇒ 每款游戏都从头自由搜。
现在：**`sources.json` 是唯一主数据**，Markdown 是 `render` 产物（`audit.render_sync` 逐字节守），
`route` 先定 ROM/set 身份再按库内状态排序出检索计划，`log` 落台账，`ingest` 把新站入库分类，
`claim-absence` 在判"查不到"前强制中文网盘层 + B站层已有 miss 记录。

**知识库（§28）在这之上加一层"正文可检索"**：`corpus_map.json` 把每份取证正文绑到
`source_id + revision（版本身份）+ authority（权威级）`，`kb build` 清洗→切块→分词→BM25 建倒排索引，
`kb query` 每条命中都回 source_id / 状态 / 权威级 / `path#L行号`，并给三态结论
（pass＝本版本权威命中；inconclusive＝只有二手或跨版本线索；miss＝本地没收集，**不等于不存在**）。
`sources route` 第②步已改成先查本地正文，索引没建时如实报 `not_built`。

## 2. 命令清单（可直接跑，工作目录 `_工具脚本`）

```bash
py -3 -m taspipe.sources show                                     # 库内概览
py -3 -m taspipe.sources route --game 热血足球联盟 --rom <本地.nes> --platform NES --want 出招表,必杀宏,金手指
py -3 -m taspipe.sources route --game kof98 --set kof98eck --platform ARCADE --want 出招表,彩蛋
py -3 -m taspipe.sources log --source-id <sid> --game <名> --want <要素> --verdict hit --evidence <取证正文>
py -3 -m taspipe.sources ingest --url <新站> --layer cn_arcade_hack --status candidate
py -3 -m taspipe.sources claim-absence --game <名> --want <要素>
py -3 -m taspipe.sources render --write                           # 重生成人读清单的 GENERATED 块
py -3 -m taspipe.sources audit                                    # 9 道门逐条 pass/fail/inconclusive
py -3 -m taspipe.sources recheck --source-id <sid>                # 探活；失败不自动判 dead
py -3 -u -m taspipe.sources_selftest_gates                        # 66 条闸门（临时目录，不动真实库）
py -3 -u -m taspipe.sources_selftest_gates --inject               # 幂等挂进 selftest.py
py -3 -m taspipe.kb build [--force]                               # 增量建正文索引（sha256 + PIPELINE 双判据）
py -3 -m taspipe.kb query --q "燕返 怎么触发" --revision nekketsu_soccer2_fc_jp --platform NES
py -3 -m taspipe.kb query --q "俱乐部 ↓↘→" --revision kof98eck --platform ARCADE --require-verified
py -3 -m taspipe.kb audit                                         # 7 道门；非 pass 退 2
py -3 -m taspipe.kb show                                          # 库内版本/块数/权威块数
py -3 -u -m taspipe.kb_selftest_gates [--inject]                  # 60 条闸门（含 4 条真实文件反查）
py -3 -u -m taspipe.selftest                                      # 全量，当前 649/649
```

## 3. 换一款游戏怎么填槽（只填数据，不改步骤）

1. **定身份**：街机给 `--set`（读本地 FBNeo `config/games/<set>.ini` + `fbneo64.roms.dat` + `roms/<set>.zip` sha1）；
   主机给 `--rom`（sha1 + 扩展名猜平台）。身份不明 ⇒ `blocked`，**不出计划、不开搜**。
2. **按 route 的 primary 段逐站查**：`verified_read` 优先，`unreachable` 只走快照，`dead` 禁止直连。
3. **每站都 log**：hit 必须带真实存在且非空的取证正文（落 `游戏包/来源库/取证/`），否则判 inconclusive 不算命中；
   miss/snippet 也要落，因为 `claim-absence` 靠这些记录放行。
4. **primary 全 miss 才走 extension**；发现新站立即 `ingest`（自动按域名生成 source_id、分层、标 candidate）。
5. **要素写进知识包**：`catalog.sources`（或顶层 `sources`）用结构化条目
   `{source_id,url,status,verified_date,element_ids,note}`，`source_id` 必须在库内，`element_ids` 逐要素归属。
6. **正文进知识库**：取证 md 落盘后在 `游戏包/知识库/corpus_map.json` 登记一条
   `{path, source_id, revision, kind(prose|table|code), authority}`；`revision` 必须先在 `revisions` 里定义
   （game_id + platform + name），`authority` 四档见 §28.1；不想入索引就写 `index:false` + `reason`（不许静默跳过）。
   然后 `kb build` → `kb query` 验一次真命中 → `kb audit`。
7. **收尾**：`render --write` + `sources audit` + `kb audit`；新坑按 S10 二选一落地（selftest 断言 或 说明书条目）。
   **改过说明书/模板等已入索引的正文后必须再 `kb build`**，否则 `index_sync` 会正确地红。

## 4. 探针隔离契约（写新闸门必须照抄）

- 五个常量全部 patch 进临时目录：`REG_JSON`、`LEDGER_JSON`、`MD_PATH`、`PACKS_DIR`、`FBNEO_CFG`；`finally` 里还原。
  知识库闸门另 patch `kb.KB_DIR`、`kb.CORPUS_MAP`、`kb.INDEX_JSON`（+ 上面两个 sources 常量），
  并临时改 `kb.PIPELINE` 验"流水线版本变了必须重建"，`finally` 还原。
- 跑完**反查真实文件**：`sources.json` 与 `复古游戏文献来源库.md` 的 `(st_mtime_ns, sha256)` 与跑前一致，
  真实 `检索台账.json` 未被创建（这三条就是 [64]–[66]）；知识库侧反查 `index.json`／`corpus_map.json`／
  `sources.json`／`检索台账.json` 四份 mtime+sha256 未变。
- **探针里改过的夹具要还原**：kb 闸门为验增量/同步门会追加源文件字节、改索引块正文，断言完必须写回原字节再重建，
  否则后续闸门踩的是脏基线。
- 每条正向闸门配**恒量反证格**：改一个词让门变红（如手改生成块 ⇒ `render_sync` fail；野 source_id ⇒ `no_wild_sources` fail）。
- 反证格要**把对照件移走**再断言：[47] 起初失败就是因为对照包还在贡献 supported 计数（临时改名 `good.off`，跑完改回）。
- 新增闸门后**必须量绿灯计数有没有涨**：注入前基线 → `--inject` → 全量重跑，数字对不上就是没登记进入口。

## 5. 不许做的事

- 手改 Markdown 的 GENERATED 块（改主数据后 `render --write`）。
- `log --verdict hit` 不带取证文件；把 snippet/快照当"已全文核对"。
- 知识包里写自由文本 URL 或库外 source_id；引用 `dead` 站。
- 探活失败就判 dead（失败 ≠ 站没了；升 dead 要人给当期证据 + reason + closure.date）。
- 跳过 `route` 直接自由搜；身份未定就出检索计划。
- 没有中文网盘层/B站 miss 记录就声称"这游戏没有该要素"。
- 手改 `index.json`（GENERATED，改语料后 `kb build`）；把 `cross_version` 的别版本表当本卡权威依据。
- 把 `kb query` 的 `miss` 读成"这游戏没有该内容"；把 `inconclusive` 当 pass 写进文案。
- 取证正文只 log 不进 `corpus_map`（`evidence_coverage` 会判红：收而不入库＝白收）。
- 改清洗器/分词器/切块参数却不升 `CLEAN_VERSION/TOKEN_VERSION/CHUNK_VERSION`（旧块会冒充新口径）。
